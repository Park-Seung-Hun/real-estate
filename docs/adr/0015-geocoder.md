# 0015. 주소를 좌표로 바꾸는 곳과 좌표 저장

매물 좌표는 저장하지 않습니다. 화면이 지도를 그릴 때마다 API 서버가 브이월드 지오코더를 불러 좌표만 화면에 줍니다.

## 배경

- 매물 화면은 매물 위치를 브이월드 지도에 표시합니다([PRD 지도 API](../prd.md#지도-api)). 지도에 표시하려면 매물 주소를 좌표로 바꿔야 하고, 바꾸는 곳(웹 화면이나 API 서버)은 [C4 컨테이너](../architecture/c4-container.md)에서 정하지 않았습니다.
- [데이터 모델](../architecture/data-model.md)은 변환한 좌표를 `listing.lat`, `listing.lng`에 저장하고 변환하지 못하면 비워 두기로 했습니다. [와이어프레임](../design/wireframes.md)의 매물 등록 화면도 주소를 찾지 못하면 지도에서 위치를 지정하라고 안내했습니다.
- 브이월드 [지오코더 API 2.0 안내 페이지](https://www.vworld.kr/dev/v4dv_geocoderguide2_s001.do)의 소개 문단은 "단, API 요청은 실시간으로 사용하셔야 하며 별도의 저장장치나 데이터베이스에 저장할 수 없습니다."라고 적습니다(2026-10-20 확인). 그래서 지오코더가 돌려준 좌표는 데이터베이스에 저장할 수 없습니다.
- 지오코더의 하루 요청 한도는 40,000건입니다.

## 선택지

| 선택지 | 내용 | 선택 |
|---|---|---|
| API 서버가 그때그때 변환 | 화면이 지도를 그릴 때마다 API 서버가 화면이 보낸 주소나 저장된 매물 주소(복호화)를 지오코더로 보내고, 좌표만 화면에 줍니다 | 채택. 좌표를 저장하지 않으므로 이용 조건을 지키고, 인증키가 브라우저에 드러나지 않습니다 |
| 웹 화면이 JSONP로 부름 | 웹 화면이 지오코더를 직접 부릅니다 | 서버 호출이 안 될 때의 대체. 인증키가 브라우저에 드러나고, CSP 허용 목록에 지오코더 주소를 더해야 합니다 |
| 좌표 저장 | 변환한 좌표를 `listing.lat`, `listing.lng`에 저장합니다 | 제외. 위 안내 문장이 지오코더 결과의 저장을 금지합니다 |
| 지도에서 직접 찍은 위치만 저장 | 지오코더 결과는 저장하지 않고, 사용자가 지도에서 찍은 위치만 저장합니다 | 제외. 저장한 좌표와 그때그때 변환한 좌표가 함께 있게 되어 화면이 좌표마다 출처를 나눠야 합니다. 사용자도 지도에서 위치를 지정하는 기능을 빼기로 했습니다(2026-11-02) |

## 결정

- 좌표를 저장하지 않습니다. 데이터 모델에서 `listing.lat`, `listing.lng`를 뺍니다.
- 화면이 지도를 그릴 때마다 API 서버가 브이월드 지오코더를 불러 좌표만 화면에 줍니다.
- 지도에서 직접 위치를 지정하는 기능은 두지 않습니다. 주소로 위치를 찾지 못하면 지도 자리에 "주소의 위치를 찾지 못했습니다. 주소를 확인하세요."를 보이고, 매물 저장은 막지 않습니다.
- 변환할 주소는 화면이 보낸 주소(저장 전 입력)나 저장된 매물 주소입니다.
- 사용자마다 하루 호출 상한을 둡니다. 로그인 허용 목록이 없어 다른 사람이 하루 한도를 다 쓰면 지도가 꺼지기 때문입니다. 값은 기능 명세에서 정합니다.
- 지오코더 요청에는 주소 평문이 실리므로 [결정 기록 0012](0012-personal-data-storage.md)의 로그 규칙(평문을 로그에 남기지 않음)을 나가는 요청 URL에도 적용합니다.
- 구현 전에 인증키로 API 서버에서 지오코더를 부를 수 있는지 확인합니다. 부를 수 없으면 웹 화면이 JSONP로 지오코더를 부르고, CSP 허용 목록에 지오코더 주소를 넣습니다.

## 결과

- [데이터 모델](../architecture/data-model.md)의 `listing`에서 `lat`, `lng` 열을 뺍니다.
- [와이어프레임](../design/wireframes.md)의 매물 등록 화면에서 지도에서 위치를 지정하라는 안내와 위치 좌표 입력을 빼고, 매물 상세의 위치 좌표 출처를 API 서버의 변환으로 고칩니다.
- [C4 컨테이너](../architecture/c4-container.md)에 API 서버가 지오코더를 부르는 관계를 그립니다.
- 지도를 그리는 순서는 [핵심 흐름](../architecture/flows.md)에 그립니다.
- 지도를 열 때마다 지오코더를 한 번 부릅니다. 사용자마다 하루 호출 상한을 두므로 한 사람이 하루 한도 40,000건을 다 쓸 수 없습니다. 사용자가 늘면 상한 값과 호출 수를 다시 셉니다.
- 2단계 단지 연결의 좌표 거리 방법([결정 기록 0008](0008-complex-matching.md))도 지오코더 좌표를 저장하지 못한다는 제약을 받습니다.
- 대체 방식(JSONP)으로 가면 [결정 기록 0013](0013-session.md)의 CSP 허용 목록에 지오코더 주소를 더하고, 이 기록의 결정 절을 고칩니다. 이 경로에서는 사용자별 상한과 요청 URL 로그 규칙을 서버가 지킬 수 없습니다.
- 사용자별 상한을 세는 값은 1단계에서 API 서버 메모리에 둡니다. 3단계에 API 서버가 두 대가 되면 다시 정합니다.
