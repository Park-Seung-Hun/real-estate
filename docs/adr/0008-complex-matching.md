# 0008. 기관마다 다른 단지 키를 잇는 방식

1단계는 실거래의 단지 번호(`aptSeq`)만 기록하고, 다른 기관의 단지 키는 단지 테이블에 열만 두고 값은 비웁니다. 잇는 방법은 2단계에서 관심 단지를 정답으로 두고 정확도와 연결 범위를 재서 고릅니다.

## 배경

단지를 다루는 기관 데이터마다 단지를 찾는 키가 다릅니다([PRD 외부 데이터 출처](../prd.md#외부-데이터-출처)).

| 데이터 | 단계 | 단지를 찾는 키 |
|---|---|---|
| 아파트 매매 실거래가 상세 | 1 | 단지 일련번호 `aptSeq` |
| 건축물대장 | 2 | 시군구 코드, 법정동 코드, 번과 지 |
| 공동주택 기본 정보와 관리비(K-apt) | 2 | K-apt 단지코드 `kaptCode` |
| 청약홈 분양정보 | 2 | 단지가 아니라 공고 단위 |

- 같은 단지의 정보를 한 화면에 모으려면 기관 키를 서로 이어야 합니다. 서로 다른 키라 이을 규칙이 필요합니다.
- 1단계 기능(실거래 추이, 호가와 실거래 비교, 거래 알림)은 실거래 데이터만 사용합니다. 건축물대장과 K-apt는 2단계의 단지 기본 정보부터 사용합니다.

## 선택지

| 선택지 | 내용 | 선택 |
|---|---|---|
| 1단계에서 잇는 방법을 정해 연결 | 아래 세 자동 방법 중 하나를 지금 골라 1단계부터 다른 기관 키를 기록합니다 | 제외. 1단계에는 이은 키를 사용하는 기능이 없습니다. 정확도를 재지 않은 채 방법을 고르게 됩니다 |
| 1단계는 열만 두고 값은 비움 | 단지 테이블에 실거래 키만 기록하고, 건축물대장 키와 K-apt 단지코드 열은 비워 둡니다 | 채택. 1단계 기능에 필요한 키는 `aptSeq` 하나입니다. 2단계에서는 열을 더하지 않고 값만 기록합니다 |
| 주소 일치 | 실거래의 법정동과 지번을 다른 기관 데이터의 주소와 맞춥니다 | 2단계에서 비교합니다 |
| 좌표 거리 | 단지 위치를 좌표로 바꿔 가까운 단지끼리 잇습니다 | 2단계에서 비교합니다 |
| 이름 정규화 | 단지 이름의 공백과 표기 차이를 정리한 뒤 이름이 같은 단지끼리 잇습니다 | 2단계에서 비교합니다 |
| 수동 보정 표 | 자동으로 잇지 못했거나 잘못 이은 단지를 표에 직접 적습니다 | 자동 방법을 보완하는 수단이라 어느 방법을 고르든 함께 둡니다. 자동 연결 결과가 없어 정확도 비교 대상은 아닙니다 |

## 결정

- 1단계는 단지 테이블(`complex`)에 실거래 단지 번호(`apt_seq`)만 기록합니다. `apt_seq`는 단지마다 하나입니다.
- 건축물대장 키(`bldg_key`)와 K-apt 단지코드(`kapt_code`)는 `complex`에 열만 두고 2단계까지 비워 둡니다.
- 자동으로 잇는 방법(주소 일치, 좌표 거리, 이름 정규화)은 2단계(단지 기본 정보)를 시작할 때 고릅니다. 관심 단지의 올바른 연결을 정답으로 두고, 방법마다 두 값을 재서 비교합니다. 하나는 이은 결과가 정답과 맞는 비율(정확도)이고, 다른 하나는 관심 단지 가운데 연결한 단지의 비율(연결 범위)입니다. 수동 보정 표는 자동으로 잇지 못했거나 잘못 이은 단지를 직접 적어 고치는 보완 수단이라, 어느 방법을 고르든 함께 둡니다.
- 청약 공고는 단지가 아니라 공고 단위라 `complex`에 청약 키 열을 두지 않습니다. 청약 알림은 관심 지역의 새 공고를 대상으로 합니다([PRD 핵심 시나리오](../prd.md#핵심-시나리오) 7).

## 결과

- 데이터 모델(`docs/architecture/data-model.md`, 작성 예정)의 `complex`에 `apt_seq`(유일), `bldg_key`, `kapt_code`를 두고, 뒤의 두 열은 빈 값을 허용합니다. `bldg_key`에 시군구 코드, 법정동 코드, 번과 지를 담는 형식도 데이터 모델에서 정합니다.
- 2단계 계획에 자동으로 잇는 세 방법의 정확도와 연결 범위 측정을 넣고, 고른 방법과 측정 결과를 새 결정 기록에 남깁니다.
