# 0010. 로그인 방식

구글 계정의 OpenID Connect로 로그인합니다.

## 배경

로그인 방식은 [PRD 열린 질문](../prd.md#열린-질문)에 남아 있고, [와이어프레임](../design/wireframes.md)의 로그인 화면은 입력란 없이 자리만 그렸습니다. 데이터 모델의 사용자 테이블과 로그인 흐름([결정 기록 0013](0013-session.md))이 로그인 방식에 따라 달라지므로, 두 문서를 쓰기 전에 정해야 합니다.

제약은 아래와 같습니다.

- 사용자는 본인과 가족 구성원, 두 명입니다([PRD 사용자](../prd.md#사용자)).
- 알림의 기본 채널이 메일이라([결정 기록 0003](0003-notification-channel.md)) 사용자마다 알림 받을 이메일 주소가 필요합니다.
- 로그인 토큰과 이메일은 개인정보이고, 컬럼마다 저장 방식을 데이터 모델에서 정합니다([PRD 비기능 요구사항](../prd.md#비기능-요구사항)의 개인정보).
- 카카오톡 알림은 2단계 후보입니다. 카카오톡 "나에게 보내기"는 카카오 로그인으로 받은 토큰으로 호출하므로 제공자 선택과 이어집니다.

외부 제공자 로그인은 OIDC(OpenID Connect, 외부 제공자 계정으로 로그인하는 표준)를 기준으로 비교했습니다. 로그인이 끝나면 제공자는 사용자 정보를 담은 ID 토큰을 돌려줍니다.

## 선택지

| 선택지 | 내용 | 선택 |
|---|---|---|
| 메일 링크 로그인 | 입력한 이메일로 일회용 로그인 링크를 보내고, 링크를 열면 로그인합니다 | 제외. 메일 발송이 늦거나 실패하면 로그인도 못 하므로 서비스가 메일 발송 경로에 더 의존하게 됩니다. 외부 제공자가 로그인 단계에서 하는 계정 보호(비밀번호 확인, 2단계 인증)도 받지 못합니다 |
| 이메일과 비밀번호 | 서비스가 비밀번호를 받아 저장하고 확인합니다 | 제외. 비밀번호 저장과 재설정 흐름을 서비스가 직접 만들고 지켜야 하는데, 사용자 두 명인 서비스에는 그 부담이 큽니다. 외부 제공자 로그인을 쓰면 이 일이 없습니다 |
| 구글 OIDC | 구글 계정으로 로그인합니다 | 채택 |
| 카카오 OIDC | 카카오계정으로 로그인합니다 | 제외. 이메일 동의항목을 설정하려면 앱이 비즈 앱 또는 테스트 앱이어야 합니다. 카카오톡 알림은 2단계에서 따로 검토합니다 |

두 후보를 같은 기준으로 비교하면 아래와 같습니다. 2026-10-19에 각 행의 공식 개발자 문서에서 확인했습니다. scope는 로그인할 때 제공자에게 요청하는 정보의 범위이고, 클레임은 토큰에 담긴 값입니다.

| 기준 | 구글 | 카카오 | 근거 |
|---|---|---|---|
| 이메일을 받는 조건 | `email` scope를 요청하면 ID 토큰에 `email`과 `email_verified` 클레임이 포함됩니다. 문서는 이메일을 사용자 식별자로 쓰지 말고 `sub`를 쓰라고 경고합니다 | 이메일 동의항목은 비즈 앱 또는 테스트 앱에서만 설정할 수 있습니다. 비즈 앱은 사업자등록 없이 개인 개발자 비즈 앱으로 전환할 수 있습니다(앱 소유자 본인인증, 카카오비즈니스 통합 서비스 약관 동의). 이메일을 선택 동의로 두고 사용자가 거부하면 로그인은 되지만 이메일은 오지 않습니다. ID 토큰의 이메일은 유효한 이메일이 있을 때만 포함됩니다 | [구글 OIDC](https://developers.google.com/identity/openid-connect/openid-connect), [카카오 동의항목](https://developers.kakao.com/docs/ko/kakaologin/utilize), [카카오 앱](https://developers.kakao.com/docs/ko/app-setting/app), [카카오 REST API](https://developers.kakao.com/docs/ko/kakaologin/rest-api) |
| 이메일 검증 여부 표시 | ID 토큰의 `email_verified`(true 또는 false) | 사용자 정보의 `is_email_verified`(인증 여부)와 `is_email_valid`(다른 카카오계정에서 쓰게 되어 만료되면 false). 인증되지 않은 이메일은 서비스가 보낸 메일을 받지 못할 수 있고, 이메일을 식별자로 쓰는 것은 권장하지 않습니다. | 앱 등록과 심사 조건 | scope가 `openid`로 시작해야 하고, 콘솔에서 따로 켜는 설정은 문서에 없습니다. 앱이 Testing 상태면 등록한 테스트 사용자(최대 100명)만 쓸 수 있지만, `openid`, `email`, `profile`만 요청하는 앱은 예외입니다. Published 상태에서 브랜드 검증을 받지 않으면 동의 화면에 앱 이름과 로고가 나오지 않습니다. 이 세 scope가 검수 대상인지는 문서에 명시돼 있지 않습니다 | 카카오 로그인을 켠 뒤 OpenID Connect를 따로 켜야 ID 토큰이 나옵니다. 카카오 로그인 자체의 검수 여부는 문서에 없습니다. 권한이 필요한 동의항목은 비즈 앱 전환 뒤 추가 기능 신청과 심사(영업일 3~5일)로 권한을 받습니다 | [구글 앱 상태](https://developers.google.com/identity/protocols/oauth2/production-readiness/overview), [카카오 사전 설정](https://developers.kakao.com/docs/ko/kakaologin/prerequisite) |

| 사용 한도 | 로그인 호출 한도는 문서에 없습니다. 리프레시 토큰은 계정당 클라이언트당 100개까지입니다 | 앱 전체에서 모든 API를 합쳐 월 300만 호출입니다. 사용자당 액세스 토큰 발급은 10분에 20회, 리프레시 토큰 갱신은 60분에 30회로 제한됩니다 | [구글 OIDC](https://developers.google.com/identity/openid-connect/openid-connect), [구글 OAuth2](https://developers.google.com/identity/protocols/oauth2), [카카오 쿼터](https://developers.kakao.com/docs/ko/getting-started/quota) |
| 로그인 버튼 규칙 | 앱 검증을 받으려면 브랜드 가이드를 따라야 합니다. 문구는 "Sign in with Google", "Sign up with Google", "Continue with Google" 중 하나이고 번역해도 됩니다. 표준 "G" 로고의 크기와 색을 바꾸지 않고, 다른 제3자 로그인 버튼보다 덜 눈에 띄게 두면 안 됩니다 | 확인하지 않았습니다 | [구글 브랜드 가이드](https://developers.google.com/identity/branding-guidelines) |
| 카카오톡 알림과의 관계 | 해당 없음 | 같은 앱에 `talk_message` 동의항목을 설정하면, 로그인한 사용자의 토큰으로 "나에게 보내기"를 호출합니다. 문서에는 나에게 보내기에 별도 사용 권한이나 검수 요구가 적혀 있지 않고, 쿼터는 "제한 없음"입니다. 친구에게 보내기는 비즈 앱 전환과 추가 기능 심사가 필요합니다 | [카카오 메시지 이해하기](https://developers.kakao.com/docs/ko/kakaotalk-message/common), [카카오 메시지 REST API](https://developers.kakao.com/docs/ko/kakaotalk-message/rest-api) |

두 후보는 이메일을 받는 조건에서 가장 크게 다릅니다. 구글은 `email` scope만 요청하면 이메일과 검증 여부를 받습니다. 카카오는 앱을 비즈 앱(개인 개발자 비즈 앱 포함)이나 테스트 앱으로 둬야 이메일 동의항목을 설정할 수 있습니다. 대신 카카오를 고르면 2단계 후보인 카카오톡 알림을 같은 앱과 같은 동의 흐름에 더할 수 있습니다.

## 결정

구글 계정의 OIDC로 로그인합니다. `email` scope 하나로 이메일과 검증 여부(`email_verified`)를 받고, `openid`, `email`, `profile`만 요청하는 앱은 테스트 상태의 사용자 제한을 받지 않습니다. 카카오는 이메일 동의항목을 비즈 앱 또는 테스트 앱에서만 설정할 수 있습니다.

- 외부 제공자의 OIDC로 로그인합니다. 메일 링크 로그인과 이메일과 비밀번호 방식은 쓰지 않습니다.
- 사용자 식별자는 이메일이 아니라 제공자가 계정마다 주는 subject 값(`sub`)입니다. 두 제공자의 문서 모두 이메일을 식별자로 쓰지 말라고 합니다.
- 로그인 이메일(구글이 준 `email` 값과 `email_verified`)은 사용자가 서비스 안에서 고칠 수 없습니다. 알림 메일 주소는 그 값을 기본값으로 복사해 알림 설정에 따로 두고, 사용자가 알림 설정에서 바꿀 수 있습니다.
- 표시 이름의 기본값은 `profile` scope의 `name` 클레임입니다.
- 카카오톡 알림은 1단계에 넣지 않고 2단계 후보로 둡니다. 그때는 로그인과 별개로 카카오 연동을 따로 검토합니다. 발송 채널을 교체할 수 있는 구조([결정 기록 0003](0003-notification-channel.md)의 발송 채널 분리)는 그대로 유지합니다.
- 로그인 뒤 세션을 쿠키 세션으로 유지할지 서비스가 발급하는 자체 토큰으로 유지할지는 [결정 기록 0013](0013-session.md)에서 정했습니다.

## 결과

- 와이어프레임의 로그인 화면에 구글 로그인 버튼을 그립니다. 버튼은 구글 브랜드 가이드를 따릅니다. "정하지 않은 것" 표에서 알림 메일 주소를 로그인 정보에서 가져올지 묻는 행을 이 기록에 맞춰 고칩니다.
- PRD 열린 질문의 로그인 방식 행과 카카오톡 알림 행을 이 기록에 맞춰 고칩니다.
- 데이터 모델의 사용자 테이블에 제공자, subject, 로그인 이메일, 이메일 검증 여부, 표시 이름을 둡니다. 알림 메일 주소는 알림 설정에 따로 둡니다. 표시 이름은 제공자 이름을 기본값으로 하고 사용자가 고칠 수 있습니다. 같은 사용자는 제공자와 subject의 쌍으로 찾습니다. 로그인 토큰과 이메일의 저장 방식(암호화 여부)도 데이터 모델에서 정합니다.
- 구글이 `email` scope로 이메일을 주므로 1단계에는 이메일을 받지 못했을 때의 입력 흐름을 두지 않습니다. 제공자를 바꾸거나 더할 때 다시 봅니다.
- [결정 기록 0013](0013-session.md)에 로그인 흐름(제공자 로그인 화면으로 보내기, 돌아온 요청에서 ID 토큰 검증, 세션 발급)을 적었습니다.
- 구글 클라우드 콘솔에 OAuth 클라이언트를 등록하는 일은 사용자가 직접 합니다.

## 상태

확정, 2026-10-19

2026-10-19에 구글을 골라 확정했습니다. 카카오톡 알림을 2단계에 넣기로 하면 카카오 연동은 새 결정 기록으로 남깁니다.

2026-10-20에 세션 방식과 로그인 흐름을 [결정 기록 0013](0013-session.md)에서 정해, 넘겼던 곳을 고쳤습니다.
