# 결정 기록

서비스 설계에서 선택지를 비교해 정한 결정과 그 이유를 기록합니다. 폴더 이름의 adr은 Architecture Decision Record(결정 기록)의 줄임말입니다.

- 선택지가 둘 이상인 설계 판단을 정할 때 새 결정 기록을 씁니다. 3단계와 4단계의 기술은 도입하기 전에 도입 조건을 측정하고, 그 결과도 결정 기록으로 남깁니다([PRD 기능 범위](../prd.md#기능-범위)).
- 확정한 결정을 바꾸거나 넓힐 때는 질문이 같은지로 나눕니다.
  - 같은 질문의 답이 바뀌거나 넓어지면 같은 기록을 고칩니다. 결정 절과 결과 절을 새 내용으로 고치고, 상태 절에 날짜와 바뀐 내용과 이유를 한 줄로 덧붙입니다. 바꾸기 전에 고른 선택지는 선택지 표에서 지우지 않고 언제까지 채택했는지 적어 둡니다.
  - 질문 자체가 달라지면 새 번호로 씁니다. 옛 기록의 상태 절에 새 번호를 적습니다.
  - 같은 질문인지는 기록 제목이 그대로 맞는지로 봅니다. 예를 들어 세션 유효 기간을 30일에서 14일로 바꾸면 0013을 고치고, 웹 세션과 별도로 앱용 토큰을 두기로 하면 새 기록을 씁니다.

## 형식

파일 이름은 `NNNN-영문-이름.md`이고, 번호는 목록의 마지막 번호 다음을 씁니다. 파일 머리에 `# NNNN. 제목`과 결정을 요약한 한 줄을 둡니다. 본문은 아래 다섯 절로 쓰고 다른 절은 더하지 않습니다.

| 절 | 담는 것 |
|---|---|
| 배경 | 결정이 필요해진 사정과 제약 |
| 선택지 | 검토한 선택지. 선택지, 내용, 선택 여부를 표로 적습니다 |
| 결정 | 정한 내용 |
| 결과 | 결정에 따라 바뀌는 기능과 문서, 새로 필요한 일 |
| 상태 | 상태 값과 날짜. 필요하면 보충 문장을 덧붙입니다 |

## 상태 값

| 상태 | 뜻 | 날짜 |
|---|---|---|
| 작성 예정 | 목록에만 있고 파일은 아직 없습니다 | 비워 둡니다 |
| 제안 | 기록은 썼지만 아직 정하지 않았습니다 | 기록을 쓴 날짜 |
| 확정 | 정했습니다 | 결정한 날짜 |
| 보류 | 정하지 않기로 미뤘습니다. 상태 절에 다시 볼 조건을 적습니다 | 보류하기로 한 날짜 |
