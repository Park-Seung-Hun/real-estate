# 0006. 같은 실거래를 구분하는 키

단지, 계약일, 층, 전용면적, 거래 금액, 해제 여부 여섯 항목으로 같은 거래를 구분하고, 여섯 항목이 모두 같은 거래는 한 행에 건수를 함께 저장합니다.

## 배경

collector는 최근 몇 달치 실거래를 매일 재수집해 바뀐 거래를 찾습니다([PRD 비기능 요구사항](../prd.md#비기능-요구사항)의 실거래 최신성과 같은 거래 구분). 어제 수집한 거래와 오늘 수집한 거래가 같은 거래인지 구분해야 새 거래와 해제를 가려낼 수 있습니다. 아파트 매매 실거래가 상세 API의 응답에는 아래 제약이 있습니다.

- 거래 고유 번호와 신고일이 없습니다.
- 동(`aptDong`)은 등기를 마친 거래에만 값이 있습니다.
- 해제된 거래는 해제 여부(`cdealType`)에 값이 있는 행으로 옵니다. 한 응답 안에 같은 조건의 해제된 행과 해제되지 않은 행이 함께 오기도 합니다.

한 자치구 60개월 실거래 11,865건(2026-10-19 확인)으로 키 후보마다 겹치는 거래를 셌습니다.

| 키 후보 | 결과 |
|---|---|
| 단지, 계약일, 층, 전용면적, 거래 금액 다섯 항목 | 438묶음 1,272건이 겹쳤습니다(키 값이 같은 거래들을 묶음이라고 부릅니다) |
| 다섯 항목과 해제 여부 | 겹친 438묶음 가운데 해제된 거래와 해제되지 않은 거래가 섞인 375묶음이 해제 키와 해제되지 않은 키로 나뉩니다. 나뉜 뒤에도 같은 키에 두 건 이상 남는 묶음이 있습니다 |
| 다섯 항목과 동 | 묶음이 193으로 줄지만, 한쪽만 동이 비어 있어 나뉜 것입니다. 두 거래 모두 동이 있으면서 동이 서로 다른 묶음은 없었습니다 |
| 응답 항목 전부 | 32개 항목이 모두 같은 55묶음 241건은 어떤 항목으로도 나눌 수 없습니다. 같은 날 같은 층, 같은 면적, 같은 금액으로 여러 호가 거래된 경우로 보입니다 |

## 선택지

앞의 세 행은 키를 이루는 항목이고, 뒤의 두 행은 키가 같은 거래를 저장하는 방식입니다.

| 선택지 | 내용 | 선택 |
|---|---|---|
| 다섯 항목 키 | 단지, 계약일, 층, 전용면적, 거래 금액 | 제외. 375묶음에서 해제된 거래와 해제되지 않은 거래가 같은 키가 되어 해제를 따로 구분할 수 없습니다 |
| 다섯 항목과 동 | 다섯 항목에 동을 더합니다 | 제외. 동은 등기 뒤에야 값이 생기므로 등기 전후로 같은 거래의 키가 달라집니다. 겹친 묶음도 나누지 못했습니다 |
| 여섯 항목 키 | 다섯 항목에 해제 여부를 더합니다 | 채택. 해제가 섞인 375묶음이 나뉩니다. 해제되면 해제 키의 행이 새로 생기므로 해제를 따로 구분할 수 있고, 등기 전후로 값이 바뀌는 항목도 키에 없습니다 |
| 같은 키 거래마다 행을 따로 둠 | 여섯 항목이 같은 거래를 건수만큼 행으로 두고 순번을 붙입니다 | 제외. 응답에 구분할 항목이 없어, 다음 날 건수가 줄면 어느 행이 빠졌는지 알 수 없습니다 |
| 같은 키 행에 건수 저장 | 여섯 항목이 같은 거래를 한 행으로 두고 건수를 함께 저장합니다 | 채택. 응답에서 알 수 있는 정보(키마다 몇 건인지)만 저장합니다 |

## 결정

거래 테이블(`trade`)은 아래 여섯 항목 조합마다 한 행을 둡니다.

| 항목 | 응답 필드 | `trade` 열 |
|---|---|---|
| 단지 | `aptSeq` | `complex_id`(단지 테이블 `complex`의 `apt_seq`로 찾음) |
| 계약일 | `dealYear`, `dealMonth`, `dealDay` | `deal_date` |
| 층 | `floor` | `floor` |
| 전용면적 | `excluUseAr` | `exclusive_area` |
| 거래 금액 | `dealAmount` | `amount` |
| 해제 여부 | `cdealType`(비어 있지 않으면 해제) | `canceled` |

- 다섯 항목으로 겹친 438묶음 1,272건 가운데 해제된 거래가 섞인 묶음이 375개입니다. 해제 여부를 키에 더하면 이 375묶음이 해제 키와 해제되지 않은 키로 나뉘지만, 그중 적어도 34묶음은 나뉜 뒤에도 한쪽 키에 두 건 이상 남습니다. 응답 항목이 모두 같은 55묶음 241건은 어떤 항목으로도 나뉘지 않습니다. 이렇게 같은 키에 두 건 이상 남는 거래는 한 행으로 두고 건수를 `same_key_count`에 저장합니다.
- 2026-10-19부터 11-02까지 매일 수집한 결과에서 새로 나타난 해제는 7건입니다. 해제되지 않은 키는 해제 행과 해제 여부만 다르고 나머지 다섯 항목이 같은 키입니다. 4건은 같은 날 그 키의 행이 응답에서 빠지고 해제 행이 생겼습니다. 2건은 같은 조건의 해제되지 않은 행이 그대로 남은 채 해제 행이 추가되었고, 1건은 같은 조건의 해제되지 않은 행 없이 해제 행만 나타났습니다. 어느 경우든 해제 키의 행이 새로 생기므로 해제를 따로 구분할 수 있습니다. 같은 조건의 해제되지 않은 키의 건수가 줄어든 경우에만 그 키에 `사라짐` 이력이 기록됩니다. 이 모델에서는 같은 거래의 키가 바뀌는 대신 다른 키의 행이 생기는 것으로 기록됩니다.
- 같은 키의 건수가 직전 수집 결과보다 늘거나 줄면 그 키의 거래가 바뀐 것으로 봅니다.
- 동은 키에 넣지 않습니다. 등기 뒤에야 값이 생겨 등기 전후로 키가 달라지고, 겹친 묶음을 나누지도 못했습니다. 동은 키가 아닌 열(`apt_dong`)로 둡니다.

## 결과

- [데이터 모델](../architecture/data-model.md)의 `trade`에 여섯 항목 열과 `same_key_count`를 두고, 여섯 항목 조합에 유니크 제약을 둡니다.
- 금액이나 층처럼 키 항목이 바뀐 거래는 다른 키가 됩니다. 이런 변경과 건수 변화를 어떻게 기록하는지는 [결정 기록 0007](0007-change-history.md)이 정합니다.
- 같은 키로 묶인 거래는 한 건씩 따로 가리킬 수 없습니다. 묶음 안의 어느 거래가 바뀌었는지는 건수 변화로만 알 수 있습니다.

## 상태

확정, 2026-10-19

2026-11-02에 매일 수집한 결과를 비교해 보니 해제 7건 중 4건은 같은 날 같은 조건의 해제되지 않은 행이 빠져, 해제 전 행이 늘 그대로 남는다고 적은 문장을 수정했습니다. 키 구성은 바뀌지 않았습니다.
