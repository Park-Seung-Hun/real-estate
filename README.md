# real-estate

아파트 임장 기록과 실거래 알림을 한곳에서 다루는 개인용 서비스입니다.

## 지금 상태

- 설계를 마치고 1단계 구현을 준비하고 있습니다. 앱 골격(Spring Boot, Flyway, Testcontainers)만 있고 기능 코드는 아직 없습니다. 앱을 실행하는 방법은 첫 기능을 구현할 때 이 문서에 적습니다.
- 테스트는 Java 25와 Docker가 필요하며 `./gradlew test`로 실행합니다. 데이터베이스가 걸린 테스트는 Docker로 띄운 실제 PostgreSQL에서 실행합니다.
- 백로그는 1단계를 SpecKit 기능 여섯 개로 나누고 구현 순서를 정합니다([백로그](docs/backlog.md)). 진행 상태는 백로그의 상태 열과 GitHub Milestone [`v1`](https://github.com/Park-Seung-Hun/real-estate/milestone/1)에서 봅니다.
- 기능은 SpecKit으로 구현하고, 기능마다 명세와 계획을 `specs/`에 남깁니다.

## 왜 만드나

- 임장 기록과 그 단지의 실거래 정보가 서로 다른 곳에 있어서, 기록을 다시 볼 때마다 시세를 따로 찾아봐야 합니다.
- 임장한 단지에 새 거래가 신고되거나 기존 거래가 해제되어도 직접 찾아보기 전에는 알 수 없습니다.

## 하려는 것

단계는 만들어 가는 순서입니다. 상세 범위는 [PRD 기능 범위](docs/prd.md#기능-범위)에 있습니다.

| 단계 | 기능 |
|---|---|
| 1 | 로그인과 가족 공유, 매물 등록과 방문 일정, 호가 직접 입력과 이력, 임장 기록(체크리스트, 사진, 메모, 점수), 실거래 수집과 추이, 호가와 실거래 비교, 거래 알림(메일) |
| 2 | 단지 기본 정보, 매물 비교, 계약 추정 표시, 청약 알림, 자금 계산, 운영 관측 |
| 3 | 거래 변경 이벤트 분리, collector와 알림 발송기 분리, 무중단 배포, 작업 중복 실행 방지와 호출 제한 |
| 4 | 서울 전체 실거래, 조회 성능 |

## 주요 결정

| 결정 | 내용 | 결정 기록 |
|---|---|---|
| 공식 API만 사용 | 실거래, 청약, 단지 정보는 기관이 공개하는 공식 API에서만 수집합니다. 호가와 KB 시세는 사용자가 직접 입력합니다 | [0001](docs/adr/0001-official-api-only.md) |
| 단계별 기술 도입 | Kafka, Redis, Kubernetes는 해당 단계를 시작할 때 도입 조건을 측정하고, 조건을 만족한 기술만 도입합니다 | [0004](docs/adr/0004-staged-adoption.md) |
| 모듈러 모놀리스 | 1단계와 2단계는 API 서버, collector, 알림 발송기를 한 애플리케이션(Java, Spring Boot) 안의 모듈로 실행합니다. 3단계부터 collector와 알림 발송기를 따로 실행합니다 | [0005](docs/adr/0005-modular-monolith.md) |
| 거래 구분과 변경 이력 | 거래 고유 번호가 없는 실거래를 여섯 항목 조합으로 구분합니다. 거래마다 최신 상태 한 행을 두고, 새 거래와 해제, 정정, 등기로 바뀐 것을 이력으로 남깁니다 | [0006](docs/adr/0006-transaction-identity.md), [0007](docs/adr/0007-change-history.md) |
| 재수집 기간 | 신고와 해제가 늦게 들어오므로 매일 이번 달을 포함한 최근 6개월을 다시 수집합니다 | [0009](docs/adr/0009-refetch-window.md) |
| 로그인과 세션 | 구글 OIDC로 로그인합니다. 브라우저에 JWT를 발급하지 않고 서버가 저장하는 세션을 사용하며, 민감한 동작 앞에서는 구글 인증을 한 번 더 거칩니다 | [0010](docs/adr/0010-login-method.md), [0013](docs/adr/0013-session.md) |
| 개인정보 저장 | 로그인 이메일, 매물 주소, 동과 호를 애플리케이션 계층에서 AES-GCM으로 암호화해 저장합니다 | [0012](docs/adr/0012-personal-data-storage.md) |
| 기반 스택 | Java 25, Spring Boot 4.1, Gradle, Flyway를 사용합니다. 데이터는 Spring Data JPA를 기본으로 접근하고, 잠금과 대량 반영과 집계는 SQL을 직접 씁니다 | [0016](docs/adr/0016-base-stack.md) |

## 데이터 원칙

- 기관이 공개하는 공식 API만 사용합니다. 부동산 앱 화면을 자동으로 수집하지 않습니다.
- 실제 임장 기록, 주소, 사진, 인증키는 저장소에 올리지 않습니다. 예시와 테스트는 가짜 데이터로 만듭니다.
