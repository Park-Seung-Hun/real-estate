# Feature Specification: 가구와 가족 공유

**Feature Branch**: `002-household-sharing`

**Created**: 2026-11-17

**Status**: Draft

**Input**: User description: "가구가 없는 사람은 가구 없음 화면에서 가구를 만들어 owner가 되고(가구 이름은 없다), owner는 초대 링크로 가족을 member로 들이며(만료 기간 선택, 초대 취소, 보낸 초대 목록 포함), 구성원은 함께 보는 사람 목록(표시 이름, 역할, 로그인 이메일과 검증 여부)을 본다. owner는 구성원을 제거하고 가구를 삭제하며, member는 가구를 나간다. 구성원은 임시 첫 화면에서 자기 표시 이름을 수정한다. 가구가 있는 사람의 탈퇴는 409로 막는다. 가구가 있는 사람의 로그인 뒤와 가구를 만든 뒤 첫 화면은 내 표시 이름, 함께 보는 사람 목록, 보낸 초대, 초대 링크 만들기, 가구 삭제 또는 가구 나가기, 로그아웃을 담은 임시 첫 화면이다(매물, 기록, 알림은 다루지 않는다)."

이 기능은 로그인(001) 위에 "누가 어느 가구의 기록을 함께 보는가"를 정합니다. 이후 기능(관심 단지, 매물, 임장 기록, 알림)의 자료가 모두 가구에 속하므로, 가구에 들어오고 나가는 규칙과 요청이 막히는 순서를 이 기능이 처음으로 끝까지 만듭니다. 로그인, 로그아웃, 로그인 상태 만료, 돌아갈 경로, 재인증 방식, 탈퇴 자체는 001이 이미 만들었고 이 기능은 그 위에 붙습니다. 화면 기준은 휴대폰 화면 폭입니다.

## Clarifications

### Session 2026-11-17

- Q: 초대 링크를 열고 구글 로그인을 마쳤을 때, 바로 가구에 합류시킬까요, 아니면 확인 화면을 한 번 거치게 할까요?
  - A: 확인 화면을 거친다. 로그인한 뒤에만 초대한 owner의 표시 이름을 보여 주고 들어가기와 취소 중에서 고르게 하며, 취소하면 초대는 대기 상태로 남는다.
- Q: member가 임시 첫 화면에서 "가구 나가기"를 누르면 바로 나가게 할까요, 아니면 확인 화면을 한 번 거치게 할까요?
  - A: 무엇을 잃는지 알리는 확인 화면을 거친 뒤 나간다. 재인증은 넣지 않는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가구를 만든다 (Priority: P1)

가구가 없는 사람이 가구 없음 화면에서 "가구 만들기"를 눌러 가구를 만들고 owner가 되어 임시 첫 화면으로 갑니다. 임시 첫 화면은 가족 초대 화면의 내용(내 표시 이름, 함께 보는 사람 목록, 보낸 초대, 초대 링크 만들기, 가구 삭제 또는 가구 나가기)에 로그아웃을 추가한 화면입니다.

**Why this priority**: 가구가 있어야 초대와 구성원 관리가 시작되고, 이후 기능이 기록을 올려 둘 곳이 생깁니다.

**Independent Test**: 가짜 구글 계정으로 로그인해 가구 없음 화면에서 가구 만들기를 누르면 임시 첫 화면에 본인만 owner로 보이는지, 이미 가구가 있는 사용자의 가구 만들기 요청이 거절되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 가구가 없는 로그인 사용자, **When** 가구 없음 화면을 열면, **Then** "아직 가구가 없습니다.", "가족과 함께 볼 기록을 모으려면 가구를 만드세요.", "가족에게 받은 초대 링크가 있으면 그 링크를 여세요." 안내와 가구 만들기, 로그아웃, 탈퇴 버튼이 보인다.
2. **Given** 가구가 없는 로그인 사용자, **When** 가구 만들기를 누르면, **Then** 가구가 하나 만들어지고 그 사람이 owner가 되며 임시 첫 화면이 열린다. 함께 보는 사람 목록에는 본인 한 명만 "(나)"와 함께 owner로 보인다.
3. **Given** 이미 가구가 있는 사용자, **When** 가구 만들기를 요청하면, **Then** 409로 거절되고 가구는 늘지 않으며 멤버십도 바뀌지 않는다.
4. **Given** 가구가 없는 사용자 한 명, **When** 가구 만들기 요청 두 건이 거의 같은 순간에 도착하면, **Then** 한 건만 성공하고 그 사람의 가구는 하나다.
5. **Given** 가구가 있는 사용자, **When** 로그인을 마치면, **Then** 임시 첫 화면이 열린다. 가구가 없는 사용자는 001과 같이 가구 없음 화면이 열린다.
6. **Given** 가구가 없는 사용자, **When** 가구에 속한 자료(함께 보는 사람 목록, 보낸 초대 목록)를 요청하면, **Then** 403으로 거절된다.
7. **Given** 가구가 없는 사용자가 가구를 만들지 않고 로그아웃과 로그인을 반복할 때, **When** 몇 번을 로그인해도, **Then** 가구는 저절로 만들어지지 않는다.

### User Story 2 - 초대 링크로 가족을 들인다 (Priority: P1)

owner가 만료 기간(1일부터 7일까지, 기본 3일)을 골라 일회용 초대 링크를 만들고 메신저나 메일로 가족에게 보냅니다. 가족이 링크를 열어 구글 로그인을 마치면 초대한 owner의 표시 이름이 보이는 확인 화면이 나오고, 들어가기를 누르면 member가 됩니다. owner는 보낸 초대 목록을 보고 수락 전의 초대를 취소할 수 있습니다.

**Why this priority**: 두 사람이 각자 로그인해 같은 기록을 함께 보는 것이 이 서비스의 핵심입니다. 가구 하나만으로는 혼자 사용하는 서비스입니다.

**Independent Test**: owner가 초대 링크를 만들고, 다른 가짜 구글 계정이 링크를 열어 로그인했을 때 member가 되는지, 만료, 취소, 재사용, 이미 가구가 있는 사람, 동시 수락이 정해진 대로 거절되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 구성원이 owner 혼자이고 수락 대기 중인 초대가 없는 가구, **When** owner가 임시 첫 화면을 열면, **Then** 만료 기간 선택(1일부터 7일까지 하루 단위, 처음 값은 3일)과 초대 링크 만들기 버튼, 그 아래 "만든 링크를 복사해 메신저나 메일로 보냅니다." 안내가 보인다.
2. **Given** 1번의 owner, 마지막 구글 인증이 5분 안, **When** 만료 기간을 고르고 초대 링크 만들기를 누르면, **Then** 초대가 하나 생기고 만료 시각은 만든 시각에 고른 날수(하루는 24시간)를 더한 시각이다. 보낸 초대에 링크와 복사 버튼과 "이 화면을 떠나면 링크를 다시 볼 수 없습니다. 가족에게만 보내세요.", 그리고 "방금 만듦"과 취소 버튼이 보인다(남은 기간은 적지 않는다).
3. **Given** 1번의 owner, 마지막 구글 인증이 5분 안, **When** 만료 기간으로 0, 8, 1.5, 문자열, 빈 값을 보내 초대 발급을 요청하면, **Then** 400으로 거절되고 초대는 생기지 않는다. 만료 기간을 보내지 않은 요청도 거절된다.
4. **Given** 링크를 만든 직후의 화면을 떠났다가 다시 열었을 때, **When** 보낸 초대 목록을 보면, **Then** 그 초대의 만든 날짜와 만료까지 남은 기간과 취소 버튼만 보이고 링크는 다시 보이지 않는다. 남은 기간은 남은 시간을 하루 단위로 올림한 날수("N일 남음")다. 예를 들어 3일을 골라 만든 직후에 다시 열면 "3일 남음", 2일 5시간이 남았으면 "3일 남음", 5시간이 남았으면 "1일 남음"이다.
5. **Given** 수락 대기 중이면서 만료되지 않은 초대가 있거나 구성원이 둘인 가구, **When** owner가 임시 첫 화면을 열면, **Then** 만료 기간 선택과 초대 링크 만들기 버튼 대신 이유 문구가 보인다. 초대가 있으면 "기다리는 초대가 있어 새 초대를 만들 수 없습니다.", 구성원이 둘이면 "구성원이 둘이라 새 초대를 만들 수 없습니다."이다. 마지막 구글 인증이 5분 안인 owner가 초대 발급을 직접 요청해도 409로 거절되고 초대는 늘지 않는다. 초대 발급 요청 두 건이 거의 같은 순간에 도착해도 초대는 하나만 생긴다.
6. **Given** member, **When** 임시 첫 화면을 열면, **Then** 만료 기간 선택, 초대 링크 만들기, 보낸 초대, 초대 취소가 없다. 초대 발급, 초대 취소, 보낸 초대 목록 요청은 403으로 거절된다.
7. **Given** 수락 대기 중인 초대, **When** owner가 취소하면, **Then** 그 링크는 사용할 수 없게 되고 새 초대를 만들 수 있다. 이미 수락되었거나 취소되었거나 만료된 초대를 취소하려는 요청은 409로 거절되고 초대는 바뀌지 않는다.
8. **Given** 로그인하지 않은 사람이 유효한 초대 링크를 열었을 때, **When** 로그인 화면에서 구글 로그인을 마치면, **Then** 다른 입력 없이 초대 확인 화면이 열린다. 로그인 상태가 만료된 사람도 같다. 로그인 화면의 초대 안내는 "가족에게 받은 초대 링크로 들어왔다면 로그인한 뒤 들어갈 가구를 확인합니다."이다.
9. **Given** 가구가 없는 로그인 사용자가 유효한 초대 링크를 열었을 때, **When** 초대 확인 화면이 열리면, **Then** "민지님의 가구에 들어갑니다. 가족에게 받은 링크가 맞을 때만 들어가세요."처럼 초대한 owner의 표시 이름과 들어가기, 취소 버튼이 보인다. owner의 로그인 이메일과 구성원 목록은 보이지 않는다. owner의 표시 이름이 비어 있으면 이름 없이 "가구에 들어갑니다."로 시작한다. 로그인하지 않은 사람에게는 이 화면이 보이지 않는다.
10. **Given** 초대 확인 화면, **When** 들어가기를 누르면, **Then** 가구를 만들지 않고 그 가구의 member가 되고 임시 첫 화면이 열린다. 취소를 누르면 member가 되지 않고 초대는 대기 상태로 남으며 가구 없음 화면으로 간다. 같은 링크를 다시 열면 확인 화면이 다시 나온다.
11. **Given** 1일을 골라 만든 초대 링크, **When** 만든 지 23시간 59분에 들어가기를 누르거나 만든 지 정확히 24시간인 순간에 누르면, **Then** 수락된다. 24시간이 지나 열면 확인 화면 대신 만료되었다는 안내가 보이고, 확인 화면을 연 채로 24시간이 지나 들어가기를 눌러도 만료 안내가 보이며 수락되지 않는다. 7일을 골라 만든 링크는 6일 23시간 59분에 수락되고 7일이 지나면 거절된다.
12. **Given** 취소된 링크, 이미 수락된 링크, 존재하지 않는 링크, 구성원이 이미 둘인 가구의 링크, **When** 열면, **Then** 확인 화면 대신 사유를 구분한 안내가 보이고 수락되지 않는다. 확인 화면을 연 뒤 그 사이에 초대가 취소되거나 수락된 경우 들어가기를 누르면 같은 안내가 보인다.
13. **Given** 다른 가구에 속한 사람, **When** 12번의 사유에 해당하지 않는 초대 링크를 열면, **Then** 확인 화면 대신 "이미 다른 가구에 속해 있습니다. 가구를 나가거나 삭제한 뒤 이 링크를 다시 여세요."처럼 안내된다. 초대는 대기 상태로 남는다. 그 사람이 가구를 나가거나 삭제한 뒤 같은 링크를 다시 열면, 만료, 취소, 사용 여부가 그대로인 한 수락된다.
14. **Given** 다른 가구에 속한 사람, **When** 만료되었거나 취소된 링크를 열면, **Then** 409 "이미 다른 가구에 속해 있습니다"가 아니라 만료나 취소 안내가 보인다. 링크 자체의 사유를 먼저 알려, 쓸 수 없는 링크 때문에 자기 가구를 나가거나 삭제하지 않게 한다.
15. **Given** owner, **When** 자기 가구에서 만든 유효한 초대 링크를 열면, **Then** 확인 화면 대신 "이미 이 가구의 구성원입니다. 링크는 가족에게 보내세요."처럼 안내된다. 가구를 나가거나 삭제하라고 안내하지 않고, 초대는 대기 상태로 남는다.
16. **Given** 서로 다른 두 사람이 같은 초대 링크로 각자 확인 화면을 열었을 때, **When** 두 사람이 들어가기를 눌러 두 수락 요청이 거의 같은 순간에 도착하면, **Then** 한 명만 member가 되고 다른 한 명은 실패 안내를 받는다. 가구 구성원은 둘을 넘지 않는다.
17. **Given** 수락한 사람이 함께 보는 사람 목록에 나타났을 때, **When** owner가 목록을 보면, **Then** 수락한 사람의 표시 이름과 로그인 이메일이 보여 가족이 맞는지 확인할 수 있다.

### User Story 3 - 함께 보는 사람을 확인하고 제거하거나 나간다 (Priority: P2)

구성원은 임시 첫 화면에서 함께 보는 사람의 표시 이름, 역할, 로그인 이메일(구글이 검증하지 않았으면 "검증되지 않음" 표시)을 봅니다. owner는 다른 구성원을 제거하고, member는 스스로 가구를 나갑니다. owner는 나가는 대신 가구를 삭제합니다.

**Why this priority**: 초대 링크가 다른 사람에게 넘어갔을 때 owner가 확인하고 제거할 수 있어야 가족 공유가 안전합니다.

**Independent Test**: 구성원이 둘인 가구에서 owner가 member를 제거하면 member의 다음 요청이 막히는지, member가 나가면 가구 없음 화면이 열리는지, owner의 나가기와 member의 제거 요청이 거절되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 구성원이 둘인 가구, **When** 구성원이 임시 첫 화면을 열면, **Then** 사람마다 표시 이름, 역할(owner 또는 member), 로그인 이메일이 보이고 내 항목에 "(나)"가 붙는다. 구글이 검증하지 않은 이메일에는 "검증되지 않음"이 함께 보인다. 표시 이름이 비어 있는 사람은 로그인 이메일만 보인다.
2. **Given** owner, 마지막 구글 인증이 5분 안, **When** member를 제거하면, **Then** 별도의 확인 화면 없이 그 사람의 멤버십만 삭제된다. 그 사람의 계정과 로그인 상태는 남는다.
3. **Given** 제거된 사람이 로그인 상태를 유지하고 있을 때, **When** 다음 요청으로 가구에 속한 자료를 요청하면, **Then** 403으로 거절되고 화면은 가구 없음 화면으로 간다.
4. **Given** owner, 마지막 구글 인증이 5분 안, **When** 자기 자신을 구성원 제거로 요청하면, **Then** 403으로 거절되고 멤버십은 그대로다.
5. **Given** member, **When** 임시 첫 화면에서 가구 나가기를 누르면, **Then** "가구를 나가면 이 가구의 기록을 볼 수 없습니다. 다시 들어오려면 새 초대 링크가 필요합니다." 안내와 나가기, 취소 버튼이 있는 확인 화면이 먼저 보인다. 재인증은 요구하지 않는다. 취소하면 임시 첫 화면으로 돌아가고 멤버십은 그대로다.
6. **Given** 가구 나가기 확인 화면, **When** 나가기를 누르면, **Then** 그 사람의 멤버십이 삭제되고 가구 없음 화면이 열린다. 그 사람의 계정과 로그인 상태는 남는다.
7. **Given** owner, **When** 임시 첫 화면을 열면, **Then** 가구 나가기 버튼이 없고, 가구 나가기를 요청해도 403으로 거절된다.
8. **Given** member, **When** 임시 첫 화면을 열면, **Then** 다른 구성원 옆에 제거 버튼이 없고, 구성원 제거를 요청해도 403으로 거절된다.
9. **Given** 제거되었거나 나간 사람, **When** 새 초대 링크를 받아 열면, **Then** 다시 member가 될 수 있다.
10. **Given** 구성원이 둘인 가구에서 member가 제거되었거나 나갔을 때, **When** owner가 임시 첫 화면을 다시 열면, **Then** 새 초대를 만들 수 있다.
11. **Given** 가구 A(owner와 member)와 가구 B(owner 혼자, 수락 대기 초대 하나), 모든 사람의 마지막 구글 인증이 5분보다 오래됨, **When** 여러 확인 단계에 걸리는 요청을 보내면, **Then** 처음 걸린 단계의 상태 코드로 응답한다. 가구 A의 member가 초대 발급을 요청하면 403이다. 가구 A의 owner가 가구 B의 owner를 구성원 제거로 요청하면 404이다. 가구 A의 owner가 자기 가구의 member를 제거하려 하면 401 REAUTH_REQUIRED이다.
12. **Given** 가구 A의 owner(마지막 구글 인증이 5분 안), **When** 가구 B의 구성원 제거나 가구 B의 초대 취소를 요청하면, **Then** 404로 거절되고 가구 B는 바뀌지 않는다. 그 응답은 존재하지 않는 구성원이나 초대를 가리킨 요청의 응답과 상태 코드와 본문이 같다.

### User Story 4 - 가구를 삭제하고, 가구가 있는 사람의 탈퇴를 막는다 (Priority: P3)

owner는 가구를 삭제할 수 있습니다. 되돌릴 수 없으므로 무엇이 삭제되는지 알리는 확인 화면을 거치고, 마지막 구글 인증이 5분 안이어야 처리됩니다. 가구가 있는 사람은 탈퇴할 수 없고, member는 가구를 나간 뒤에, owner는 가구를 삭제한 뒤에 001의 탈퇴를 합니다.

**Why this priority**: 서비스를 그만두는 길(가구 삭제 뒤 탈퇴)이 있어야 개인정보를 사용자가 거둘 수 있습니다. 자주 사용하는 동작은 아니라 우선순위가 낮습니다.

**Independent Test**: owner가 가구를 삭제하면 구성원 모두가 가구 없음 화면을 보는지, 대기 중이던 초대 링크가 존재하지 않는 링크로 안내되는지, 가구가 있는 사용자의 탈퇴 요청이 거절되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** owner, **When** 임시 첫 화면 아래의 가구 삭제를 누르면, **Then** 구성원 수와 삭제되는 자료(가구, 구성원 연결, 보낸 초대)와 되돌릴 수 없다는 안내가 있는 확인 화면이 먼저 보이고, 확인해야 삭제가 진행된다.
2. **Given** 가구 삭제 확인 화면, **When** 취소하면, **Then** 임시 첫 화면으로 돌아가고 가구, 멤버십, 초대는 바뀌지 않는다.
3. **Given** 마지막 구글 인증이 5분보다 오래된 owner, **When** 확인 화면에서 삭제를 확인하면, **Then** 401 REAUTH_REQUIRED로 처리되지 않고 재인증을 안내한다. 재인증을 마치고 돌아오면 같은 버튼을 다시 눌러야 처리된다.
4. **Given** 확인을 마친 가구 삭제, **When** 처리되면, **Then** 가구와 그 가구의 멤버십과 초대가 모두 삭제되고 owner는 가구 없음 화면으로 간다. 구성원이었던 사람의 계정과 로그인 상태는 남고 다음 요청부터 가구 자원은 403이며 화면은 가구 없음 화면으로 간다.
5. **Given** 삭제된 가구의 대기 중이던 초대 링크, **When** 열면, **Then** 존재하지 않는 링크로 안내된다.
6. **Given** member, **When** 임시 첫 화면을 열면, **Then** 가구 삭제 버튼이 없고, 가구 삭제를 요청해도 403으로 거절된다.
7. **Given** 가구가 있는 사용자(owner 또는 member), **When** 탈퇴를 요청하면, **Then** 마지막 구글 인증 시각과 관계없이 409로 거절되고 계정과 멤버십은 그대로다. 임시 첫 화면에는 탈퇴 버튼이 없다. 가구가 있는 사람이 탈퇴 확인 화면 주소를 직접 열어 확인을 누르면 "가구를 나가거나 삭제한 뒤 탈퇴할 수 있습니다."가 보인다.
8. **Given** 가구를 나간 member나 가구를 삭제한 owner, **When** 가구 없음 화면에서 탈퇴하면, **Then** 001의 탈퇴대로 처리된다.

### User Story 5 - 내 표시 이름을 화면에서 수정한다 (Priority: P3)

임시 첫 화면의 "내 표시 이름" 입력란에서 자기 표시 이름을 수정해 저장합니다. 구글이 이름을 보내지 않아 비어 있으면 직접 입력합니다. 함께 보는 사람 목록에 이 이름이 보입니다. 저장 규칙(앞뒤 공백을 뺀 1자 이상 20자 이하, 빈 이름 거절)은 001이 만든 표시 이름 수정 요청을 그대로 씁니다.

**Why this priority**: 구글 계정 이름이 가족끼리 부르는 이름과 다를 수 있어, 서로 구분할 수 있게 하는 보조 기능입니다.

**Independent Test**: 이름을 수정해 저장하면 양쪽 구성원의 함께 보는 사람 목록에 새 이름이 보이는지, 빈 이름과 21자 이름이 거절되는지, 다른 구성원의 이름을 바꾸는 길이 없는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 구성원, **When** 임시 첫 화면을 열면, **Then** "내 표시 이름"에 지금 이름이 보이고(비어 있으면 비어 있음), 그 아래 빈 "새 이름" 입력란과 저장 버튼이 있다.
2. **Given** 구성원, **When** 새 이름을 입력해 저장하면, **Then** 본인과 상대 양쪽의 함께 보는 사람 목록에 새 이름이 보인다.
3. **Given** 구성원, **When** 빈 이름이나 21자 이름을 저장하려 하면, **Then** 저장되지 않고 화면에 이유가 보이며 이전 이름이 그대로다.
4. **Given** 구성원, **When** 다른 구성원의 표시 이름을 바꾸려 하면, **Then** 그런 화면과 요청이 없다. 표시 이름 수정 요청은 요청한 사람 자신의 이름만 바꾼다.

### Edge Cases

- 한 번 재인증하면 5분 안에는 이 기능의 민감 동작 셋(초대 발급, 구성원 제거, 가구 삭제)을 각각 재인증 없이 처리할 수 있습니다.
- 초대를 만든 owner가 가구를 삭제하면 대기 중인 초대도 함께 사라집니다.
- 초대를 기다리던 사용자가 실수로 가구를 먼저 만들었다면, 자기 가구를 삭제한 뒤 받은 링크를 다시 열어 들어갑니다(US2 13번).
- 구글이 이메일을 검증하지 않았다고 보낸 사용자도 가구를 만들고 초대를 수락할 수 있고, 함께 보는 사람 목록에서 "검증되지 않음"으로 표시됩니다.
- 초대 링크를 연 사람이 구글 로그인을 시작한 뒤 10분 안에 마치지 못하면(001의 로그인 제한) 링크를 다시 열어야 합니다.
- 다른 사람이 수락한 링크를 열면 "이미 사용됨"으로 안내되고, 그 링크의 가구에 누가 있는지는 알려 주지 않습니다.
- 모르는 사람에게서 받은 링크를 연 사람은 확인 화면에서 낯선 이름을 보고 취소할 수 있습니다. 취소하면 그 사람의 정보는 링크를 보낸 사람에게 보이지 않습니다.
- 유효한 링크를 가진 사람은 로그인만 하면 확인 화면에서 owner의 표시 이름을 볼 수 있습니다. 들어가기를 누르면 owner의 로그인 이메일까지 볼 수 있으므로, 확인 화면이 새로 노출하는 정보는 없습니다.
- 구성원이 둘인 가구에서 owner가 member를 제거한 직후 새 초대를 만들 수 있습니다.
- 이전에 만든 초대가 만료되었으면 수락 대기 중인 초대로 세지 않으므로 새 초대를 만들 수 있고, 만료된 초대는 보낸 초대 목록에 보이지 않습니다.
- 초대 링크 원문과 로그인 이메일 원문은 서비스 로그와 오류 메시지에 평문으로 남지 않습니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 멤버십이 없는 사용자가 가구 없음 화면에서 가구를 만들면 그 사람을 owner로 하는 가구를 하나 만들어야 한다. 가구에는 이름이 없다. 첫 로그인만으로 가구를 만들지 않는다. 가구를 만들 때와 초대를 수락할 때 그 사람이 가구에 들어온 시각을 멤버십에 기록한다(뒤 기능의 거래 알림이 이 시각 이후의 변경만 보낸다).
- **FR-002**: 시스템은 가구 없음 화면에 "아직 가구가 없습니다.", "가족과 함께 볼 기록을 모으려면 가구를 만드세요.", "가족에게 받은 초대 링크가 있으면 그 링크를 여세요." 안내와 가구 만들기, 로그아웃, 탈퇴 버튼을 보여 주어야 한다.
- **FR-003**: 시스템은 로그인을 마친 뒤와 가구를 만든 뒤, 가구가 있는 사용자에게 임시 첫 화면을 보여 주어야 한다. 임시 첫 화면은 내 표시 이름 입력란, 함께 보는 사람 목록, 로그아웃 버튼을 담고, owner에게는 보낸 초대와 초대 취소, 만료 기간 선택과 초대 링크 만들기(또는 만들 수 없는 이유 문구), 다른 구성원의 제거 버튼, 가구 삭제를, member에게는 자기 행의 가구 나가기를 추가한다. 로그인 전에 열려던 서비스 안 경로가 있으면 001대로 그 경로로 보낸다.
- **FR-004**: 시스템은 한 사용자가 가구 하나에만 속하게 하고, 가구 구성원을 둘까지로 제한해야 한다. 역할은 owner와 member 둘이며 읽기 전용 역할은 없다. 이 규칙은 요청이 동시에 들어와도 지켜진다.
- **FR-005**: 시스템은 이미 가구가 있는 사용자의 가구 만들기 요청을 409로 거절해야 한다.
- **FR-006**: 시스템은 owner가 초대를 발급할 때 만료 기간을 1부터 7까지의 정수(일)로 받아야 한다. 그 밖의 값(0, 8, 소수, 문자열, 빈 값)과 값이 없는 요청은 400으로 거절한다. 화면의 만료 기간 선택은 1일부터 7일까지 하루 단위이고 처음 값은 3일이다.
- **FR-007**: 시스템은 초대의 만료 시각을 만든 시각에 고른 날수(하루는 24시간)를 더한 시각으로 정하고, 현재 시각이 만료 시각보다 늦으면 그 초대를 수락하지 않아야 한다(만료 시각 정각에는 수락한다). 만료는 초대의 상태가 아니라 만료 시각과 현재 시각의 비교로 판단한다.
- **FR-008**: 시스템은 초대 링크를 추측할 수 없는 일회용 값으로 만들고, 링크 원문은 만든 직후 응답에만 담아야 한다. 이후 어떤 응답에도 링크 원문을 다시 담지 않는다.
- **FR-009**: 시스템은 구성원이 둘이거나 수락 대기 중이면서 만료되지 않은 초대가 있으면 새 초대 발급을 409로 거절하고, 화면에는 만료 기간 선택과 버튼 대신 그 이유("기다리는 초대가 있어 새 초대를 만들 수 없습니다." 또는 "구성원이 둘이라 새 초대를 만들 수 없습니다.")를 보여 주어야 한다. 수락 대기 중이면서 만료되지 않은 초대는 가구마다 한 번에 하나까지이고, 이 규칙은 발급 요청이 동시에 들어와도 지켜진다. 구성원이 둘이면서 수락 대기 중인 초대도 있는 상태(보통의 흐름으로는 생기지 않음)에서는 구성원이 둘이라는 이유를 보인다.
- **FR-010**: 시스템은 owner에게 보낸 초대 목록을 보여 주어야 한다. 목록에는 수락 대기 중이면서 만료되지 않은 초대만 나오고(수락, 취소, 만료된 초대는 나오지 않음), 초대마다 만든 날짜와 만료까지 남은 기간과 취소 버튼이 보인다. 남은 기간은 남은 시간을 하루 단위로 올림한 날수("N일 남음")이고, 만료 시각 정각처럼 남은 시간이 0이어도 아직 만료되지 않았으면 "1일 남음"이다. 링크를 만든 직후에는 만든 날짜 대신 "방금 만듦"이 보이고 남은 기간은 적지 않는다. 목록에 나올 초대가 없으면 보낸 초대 영역을 보이지 않는다.
- **FR-011**: 시스템은 owner가 수락하기 전의 초대를 취소하게 해야 한다. 취소된 링크는 사용할 수 없다. 수락 대기 중이 아니거나 만료된 초대를 취소하려는 요청은 409로 거절한다.
- **FR-012**: 시스템은 수락할 수 있는 초대 링크를 연 사람이 로그인한 상태가 되면 초대 확인 화면을 보여 주고, 들어가기를 누르면 그 가구의 member로 만들어야 한다. 이미 로그인한 사람이든 로그인하지 않았거나 로그인 상태가 만료된 사람이든 같다. 로그인이 필요하면 구글 로그인을 거치는 동안 초대가 유지되어 다른 입력 없이 확인 화면이 열린다. 확인 화면은 초대한 owner의 표시 이름(비어 있으면 이름 없음)과 들어가기, 취소만 보이고, owner의 로그인 이메일과 구성원 목록은 보이지 않으며, 로그인하지 않은 사람에게는 보이지 않는다. 취소하면 초대는 대기 상태로 남는다. 수락되면 임시 첫 화면을 보여 준다. 수락할 수 없는 링크면 확인 화면 대신 FR-013의 안내를 보이고, 들어가기를 누른 순간에도 수락 조건을 다시 확인한다. 로그인 화면의 초대 안내 문구는 "가족에게 받은 초대 링크로 들어왔다면 로그인한 뒤 들어갈 가구를 확인합니다."로 바꾼다.
- **FR-013**: 시스템은 초대를 수락할 수 없을 때 존재하지 않음, 취소, 이미 사용됨, 만료, 구성원이 이미 둘임, 이미 이 가구의 구성원임, 이미 다른 가구에 속함을 구분해 안내해야 한다. 여러 사유에 걸리면 링크 자체의 사유(존재하지 않음, 취소, 이미 사용됨, 만료, 구성원이 이미 둘임)를 먼저 안내하고, 그다음 여는 사람의 사유(이미 이 가구의 구성원임, 이미 다른 가구에 속함)를 안내한다. 안내에는 그 가구의 구성원 정보를 담지 않는다.
- **FR-014**: 시스템은 이미 가구에 속한 사람의 초대 수락을 409로 거절해야 한다. 다른 가구에 속한 사람에게는 가구를 나가거나 삭제한 뒤 같은 링크를 다시 열라고 안내하고, 그 링크의 가구에 이미 속한 사람(링크를 만든 owner)에게는 이미 이 가구의 구성원이라고만 안내한다. 이 거절은 초대의 상태를 바꾸지 않는다.
- **FR-015**: 시스템은 같은 초대 링크의 동시 수락 요청 중 한 건만 성공시키고 나머지는 실패를 안내해야 한다. 한 번 수락된 링크는 무효가 된다.
- **FR-016**: 시스템은 함께 보는 사람 목록에 사람마다 표시 이름, 역할, 로그인 이메일을 보이고, 구글이 검증하지 않은 이메일에는 "검증되지 않음"을 함께 표시해야 한다. 내 항목에는 "(나)"를 붙인다. 로그인 이메일은 사용자가 서비스 안에서 수정할 수 없다.
- **FR-017**: 시스템은 owner가 다른 구성원을 제거하면 그 사람의 멤버십만 삭제하고 계정과 로그인 상태는 남겨야 한다. owner가 자기 자신을 제거하려는 요청은 403으로 거절한다. 구성원 제거는 별도의 확인 화면을 두지 않고 재인증을 확인 절차로 삼는다.
- **FR-018**: 시스템은 member가 스스로 가구를 나갈 수 있게 해야 한다. 나가기 전에 "가구를 나가면 이 가구의 기록을 볼 수 없습니다. 다시 들어오려면 새 초대 링크가 필요합니다." 안내가 있는 확인 화면을 거치고, 재인증은 요구하지 않는다(민감 동작이 아니다). 나가면 그 사람의 멤버십만 삭제하고 계정과 로그인 상태는 남긴다. owner는 가구를 나갈 수 없고(403) 가구를 삭제한다.
- **FR-019**: 시스템은 역할을 로그인 상태에 담지 않고 요청마다 멤버십을 다시 확인해야 한다. 제거되었거나 나간 사람과 삭제된 가구의 구성원이었던 사람은 다음 요청부터 가구 자원 요청이 403으로 거절되고, 화면은 가구 없음 화면으로 간다.
- **FR-020**: 시스템은 owner가 가구를 삭제할 때 구성원 수와 삭제되는 자료(가구, 구성원 연결, 보낸 초대)와 되돌릴 수 없다는 안내가 있는 확인 화면을 거치게 하고, 확인 뒤 가구와 그 가구의 멤버십과 초대를 삭제해야 한다. member의 가구 삭제 요청은 403으로 거절한다. 삭제는 이 기능이 만드는 자료만 다루고, 뒤 기능이 자기 자료와 안내 문구를 연쇄에 추가한다.
- **FR-021**: 시스템은 가구가 있는 사용자의 탈퇴 요청을 409로 거절하고 계정과 멤버십을 그대로 두어야 한다. 이 거절은 재인증 확인보다 먼저 일어난다. 임시 첫 화면에는 탈퇴 버튼을 두지 않고, 탈퇴 확인 화면에서 이 거절을 받으면 "가구를 나가거나 삭제한 뒤 탈퇴할 수 있습니다."를 보여 준다.
- **FR-022**: 시스템은 이 기능의 민감 동작 셋(초대 발급, 구성원 제거, 가구 삭제)을 001의 재인증 방식대로 마지막 구글 인증이 5분 안일 때만 처리해야 한다. 마지막 인증 기록이 없거나, 5분보다 오래되었거나, 현재 시각보다 60초 넘게 미래이면 401과 코드 REAUTH_REQUIRED로 응답한다. 재인증 뒤 돌아오면 동작을 자동으로 다시 보내지 않고 사용자가 같은 버튼을 다시 누른다.
- **FR-023**: 시스템은 요청을 다음 순서로 확인하고 처음 걸린 단계의 상태 코드로 응답해야 한다. (1) 로그인 상태(401), (2) 멤버십(멤버십 없이 허용하는 동작이 아니면 403, 멤버십이 있는 사람의 가구 만들기와 탈퇴는 409), (3) 역할의 권한(403), (4) 경로가 가리키는 초대나 구성원이 내 가구의 것인지(404), (5) 본인 확인이 필요한 동작의 본인 확인(403. owner가 자기 자신을 구성원 제거로 요청한 거절도 이 단계라 마지막 구글 인증이 오래되어도 403), (6) 민감 동작의 재인증(401 REAUTH_REQUIRED). 예를 들어 member가 마지막 인증이 오래된 상태로 초대 발급을 요청하면 403이고, 마지막 인증이 오래된 owner가 다른 가구의 구성원 제거를 요청하면 404이며, 같은 owner가 자기 가구의 구성원 제거를 요청하면 401 REAUTH_REQUIRED이다. 입력 검증(400)과 현재 상태와의 충돌(409. 초대를 만들 수 없음, 대기 중이 아닌 초대 취소)은 이 여섯 단계를 통과한 뒤에 판단한다. 멤버십이 있는 사람의 가구 만들기와 탈퇴 409는 예외로 (2)에서 판단한다.
- **FR-024**: 시스템은 다른 가구의 초대나 구성원을 가리키는 요청에 403이 아니라 404로 응답하고, 그 응답이 존재하지 않는 초대나 구성원을 가리킨 요청의 응답과 구분되지 않아야 한다.
- **FR-025**: 시스템은 owner와 member의 권한을 결정 기록 0011의 권한 키 표대로 구분해야 한다. 이 기능의 동작에서 owner는 보낸 초대 목록, 초대 발급, 초대 취소, 구성원 제거, 가구 삭제를 하고, member는 가구 나가기를 하며, 둘 다 함께 보는 사람 목록 조회와 자기 표시 이름 수정을 한다.
- **FR-026**: 시스템은 멤버십 없이 허용하는 동작을 로그아웃, 내 정보 조회, 자기 표시 이름 수정, 초대 수락(초대 확인 화면의 조회 포함), 가구 만들기, 탈퇴로 제한해야 한다. 이 밖의 요청은 멤버십이 없으면 403으로 거절한다.
- **FR-027**: 시스템은 임시 첫 화면에서 자기 표시 이름을 수정하게 하고, 001의 표시 이름 규칙(앞뒤 공백을 뺀 1자 이상 20자 이하, 빈 이름 거절)을 그대로 적용해야 한다. 다른 구성원의 표시 이름을 바꾸는 화면과 요청은 없다.
- **FR-028**: 시스템은 초대 링크 원문, 로그인 이메일 원문, 표시 이름을 서비스 로그와 오류 메시지에 평문으로 남기지 않아야 한다.
- **FR-029**: 시스템은 이 기능이 추가하는 모든 화면(가구 없음 화면의 변경, 임시 첫 화면, 초대 확인 화면, 초대 수락 실패 안내, 가구 삭제 확인 화면, 가구 나가기 확인 화면)을 휴대폰 화면 폭에서 가로 스크롤 없이 사용할 수 있게 해야 한다.

### Key Entities *(include if feature involves data)*

- **가구**: 기록을 함께 보는 공유 단위. 이름이 없다. 구성원은 둘까지다. owner는 멤버십의 역할로 찾는다.
- **멤버십**: 사용자가 어느 가구에 어떤 역할(owner 또는 member)로 속하는지와 들어온 시각. 사용자는 가구 하나에만 속한다.
- **초대**: 가구에 가족을 들이는 일회용 링크 한 개. 초대한 가구, 만든 owner, 링크 값의 해시, 상태(대기, 수락, 취소), 만든 시각, 만료 시각을 가진다. 링크 원문은 저장하지 않는다. 만료는 상태가 아니라 만료 시각으로 판단한다.
- **사용자**(001): 표시 이름, 로그인 이메일, 이메일 검증 여부를 이 기능의 목록과 입력란이 보여 준다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 가구가 없는 사용자가 가구 없음 화면에서 가구 만들기를 누르면 추가 입력 없이 임시 첫 화면에 도착한다(화면 이동 한 번).
- **SC-002**: 초대 링크를 연 가족은 구글 로그인을 마친 뒤 확인 화면에서 들어가기 한 번만 누르면 함께 보는 사람 목록에 member로 나타난다. 로그인이 필요한 경우에도 그 밖의 입력 단계는 없다.
- **SC-003**: 고른 만료 기간(1일부터 7일까지 각각)이 지난 초대 링크는 100% 수락이 거절되고, 기간 안의 유효한 링크는 100% 수락된다. 같은 링크의 동시 수락 요청 열 건 중 정확히 한 건만 성공하고, 어떤 순서로 요청이 와도 가구 구성원은 둘을 넘지 않는다.
- **SC-004**: owner가 member를 제거하거나, member가 나가거나, owner가 가구를 삭제한 뒤, 그 사람의 가구 자원 요청은 다음 요청부터 100% 거절된다.
- **SC-005**: 초대 발급, 구성원 제거, 가구 삭제는 마지막 구글 인증이 5분 안일 때 100% 처리되고, 5분을 넘기면 100% 401 REAUTH_REQUIRED로 거절된다.
- **SC-006**: 다른 가구의 초대나 구성원을 가리키는 요청은 100% 404로 응답하고, 응답 내용으로 그 자원이 있는지 구분할 수 없다.
- **SC-007**: 여러 확인 단계에 동시에 걸리는 요청의 예 세 개(FR-023)가 모두 정해진 상태 코드로 응답한다.
- **SC-008**: 가구가 있는 사용자의 탈퇴 요청은 100% 409로 거절되고 계정이 남는다.
- **SC-009**: 서비스 로그와 오류 메시지에서 초대 링크 원문, 로그인 이메일, 표시 이름이 평문으로 발견되는 경우가 0건이다.
- **SC-010**: 이 기능이 추가하는 모든 화면이 휴대폰 화면 폭에서 가로 스크롤 없이 모든 버튼을 누를 수 있다.

## Assumptions

- 사용자는 본인과 가족 구성원 두 명이고, 모두 휴대폰 웹 브라우저로 사용합니다.
- 로그인, 로그아웃, 로그인 상태 만료, 돌아갈 경로 검증, 재인증 방식(구글 계정 다시 고르기와 같은 계정인지 확인, 마지막 구글 인증 시각은 서비스가 로그인이나 재인증을 마친 시각), 탈퇴 자체, 내 정보 조회와 표시 이름 수정 요청은 001이 만들었고 이 기능이 그대로 사용합니다([001 spec](../001-login/spec.md)).
- 초대 링크의 만료 기간을 owner가 1일부터 7일까지 고르게 한 것과 이미 가구가 있는 사람의 수락을 거절하는 것은 2026-11-17 저장소 소유자 결정입니다. 만료 기간의 처음 값 3일과 남은 기간 표시 방식은 이 명세의 기본값입니다.
- 와이어프레임의 가족 초대 화면에는 만료 기간 선택이 그려져 있지 않습니다. 구현 전에 와이어프레임의 그림과 입력 표, "정하지 않은 것" 표를 이 명세에 맞게 수정합니다(constitution IV).
- 초대 확인 화면은 2026-11-17 저장소 소유자 결정입니다. 결정 기록 0011의 "링크를 열어 로그인하면 바로 member가 되어"와 와이어프레임의 "받은 사람은 링크를 열어 구글 로그인하면 바로 수락되어", 로그인 화면의 안내 문구와 다르므로, 구현 전에 `docs/*` 브랜치에서 0011과 와이어프레임(초대 확인 화면 추가)을 수정합니다. 001이 만든 로그인 화면의 안내 문구는 이 기능이 바꿉니다.
- 임시 첫 화면은 관심 단지 목록을 만드는 004가 관심 단지 목록으로 바꾸고, 그때 가족 초대 화면으로 가는 길을 관심 단지 목록에 둡니다([백로그](../../docs/backlog.md)).
- 가구 만들기 때의 기본 체크리스트 항목은 007이, 구성원이 나가거나 제거될 때 그 사람의 임장 기록 작성자를 비우는 처리는 007이, 알림 설정은 009가 맡고, 이미 있는 가구와 사용자의 자료도 채웁니다([백로그의 경계 규칙](../../docs/backlog.md)).
- 가구 나가기 확인 화면의 안내 문구는 이 기능의 자료만 가리키고, 007이 나간 사람의 임장 기록 작성자를 비우는 처리를 추가할 때 문구도 함께 수정합니다.
- 가구를 삭제하면 삭제되는 자료의 안내 문구는 이 기능에서는 가구, 구성원 연결, 보낸 초대만 가리키고, 뒤 기능이 자기 자료를 연쇄에 추가할 때 문구도 함께 수정합니다.
- 다른 가구 자원 404와 요청이 막히는 순서(403, 404, 401 REAUTH_REQUIRED)를 확인하는 테스트는 이 기능이 넣습니다. 세션 행 삭제, 절대 30일 만료, 돌아갈 경로 테스트는 001이 넣었습니다([API 공통 규칙](../../docs/architecture/api-conventions.md#인증과-권한-확인)).
- 구성원 제거는 재인증을 확인 절차로 삼아 별도의 확인 화면을 두지 않습니다(2026-11-04 저장소 소유자 수용).
- owner가 자기 자신을 구성원 제거로 요청하면 403입니다. 결정 기록 0011의 `member:remove`는 "다른 구성원"을 제거하는 권한이고, owner가 가구를 떠나는 길(`member:leave`)은 owner에게 거부되어 있어 같은 결과로 맞췄습니다. 설계 문서에 직접 적힌 규칙이 아니라 이 명세가 정한 것입니다.
- 초대 수락 실패 사유를 안내하는 순서(링크 자체의 사유 먼저)와 owner가 자기 가구의 링크를 열었을 때의 안내는 이 명세가 정한 것입니다. 쓸 수 없는 링크 때문에 사용자가 되돌릴 수 없는 가구 삭제를 하지 않게 하려는 것입니다.
- owner 역할은 다른 구성원에게 넘길 수 없습니다. owner가 그만두려면 가구를 삭제합니다. 설계 문서에 역할 이전이 없어 범위에 넣지 않습니다.
- 초대 수락 실패 사유별 오류 코드, 링크의 모양, 로그인을 거치는 동안 초대를 유지하는 방법, 동시 수락과 동시 가구 만들기를 막는 방법은 plan이 정합니다.
- 범위 밖: 매물, 호가, 관심 단지, 임장 기록, 체크리스트, 알림, 가구 이름, 읽기 전용 역할, owner 역할 이전, 여러 가구에 속하기, 로그인한 기기 목록.
