# 원본 응답 파일 계약

원본 응답 파일의 위치와 형식입니다. 기준은 [결정 기록 0014](../../../docs/adr/0014-file-storage.md)이고 이 문서는 003이 정하는 세부만 적습니다.

| 항목 | 값 |
|---|---|
| 버킷 | 원본 응답 버킷. 이름은 설정값 `estate.collector.raw.bucket`(환경 변수 `ESTATE_RAW_S3_BUCKET`) |
| 오브젝트 키 | `{수집 날짜 YYYY-MM-DD}/{실행 시작 시각 HHmmss}/{시군구 코드}-{계약년월}-p{페이지 번호}.xml.gz` |
| 날짜와 시각의 시간대 | 한국 시간(`Asia/Seoul`). 실행 시작 시각은 예약 실행이 시작될 때 한 번 정한 값입니다([research R6](../research.md#r6-연속-수집-조건의-판정)) |
| 페이지 번호 | 1부터, 앞 0 없음(`p1`, `p2`) |
| 본문 | 외부 API가 반환한 응답 본문 바이트를 그대로 gzip으로 압축한 것. 다시 직렬화하거나 수정하지 않습니다 |
| `Content-Type` | `application/gzip` |
| 덮어쓰기 | 키가 구성상 겹치지 않아(아래 목록) 덮어쓰기 검사는 두지 않습니다 |
| 삭제 | 하지 않습니다 |
| 저장 시점 | 한 범위의 모든 페이지를 수집한 뒤, 건수 확인과 비교보다 먼저 |

- 예: `2026-11-20/090000/99999-202611-p1.xml.gz`(가짜 시군구 코드).
- 같은 실행에서 같은 범위를 두 번 수집하는 일은 없으므로 키가 겹치지 않습니다. 한 예약 실행 안에서 매일 수집과 초기 적재가 이어지면 실행 시작 시각(폴더)이 같지만, 두 실행은 서로 다른 지역(행이 있는 지역과 없는 지역)을 수집해 키가 겹치지 않습니다. 같은 날 다른 예약 실행은 실행 시작 시각이 달라 폴더가 다릅니다.
- 원본 응답에는 요청 주소가 들어 있지 않아 인증키가 저장되지 않습니다. 테스트가 이를 확인합니다(spec SC-008).
