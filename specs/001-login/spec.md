# Feature Specification: 로그인

**Feature Branch**: `001-login`

**Created**: 2026-11-04

**Status**: Draft

**Input**: User description: "사용자는 구글 계정으로 로그인하고 로그아웃하며, 로그인 상태는 쓰지 않으면 7일, 계속 써도 로그인한 지 30일이 지나면 만료되고, 민감 동작 앞에서는 구글 인증을 한 번 더 거치며(재인증), 탈퇴(자기 계정 삭제)할 수 있고, 내 정보 조회와 표시 이름 수정은 요청(API)으로 할 수 있습니다. 로그인 뒤에는 가구 없음 화면(로그아웃과 탈퇴 버튼만 있음)이 열립니다(가구, 초대, 매물, 기록, 알림은 다루지 않습니다)."

이 기능은 "이 사람이 누구인가"를 서비스가 아는 문을 만듭니다. 가구(기록을 함께 보는 묶음)와 초대는 다음 기능(002 가구와 가족 공유)이 이 위에 서므로, 이 기능에는 가구라는 개념이 없고 모든 사용자는 가구 없음 화면으로 들어옵니다. 화면 기준은 휴대폰 화면 폭입니다. 로그인 화면에 보이는 서비스 이름은 임시 이름 "서초댁 임장 기록"이고 최종 이름은 정해지지 않았습니다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 구글 계정으로 로그인하고 로그아웃한다 (Priority: P1)

본인이나 가족 구성원이 서비스 주소를 열면 로그인 화면이 보이고, 구글 계정으로 로그인하면 가구 없음 화면으로 갑니다. 쓰고 나면 로그아웃합니다. 로그인한 상태는 쓰지 않으면 7일, 계속 써도 로그인한 지 30일이 지나면 만료됩니다.

**Why this priority**: 로그인이 없으면 어떤 기능도 사용자를 구분할 수 없습니다. 이 스토리만 구현해도 "누구인지 아는 서비스"라는 최소 가치가 생깁니다.

**Independent Test**: 가짜 구글 계정으로 로그인해 가구 없음 화면이 열리는지, 로그아웃하면 로그인 화면으로 돌아가고 이전 로그인 상태로 요청해도 거절되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 로그인하지 않은 사람, **When** 서비스 주소를 열면, **Then** 로그인 화면(서비스 이름, 구글 로그인 버튼, 가족에게 받은 초대 링크로 들어왔다면 로그인하면 바로 수락된다는 안내 문구)만 보이고 다른 화면은 보이지 않는다. 다른 화면의 주소를 열어도 로그인 화면이 보이고, 로그인하지 않은 채 자료를 요청(API)하면 401로 응답한다.
2. **Given** 처음 로그인하는 구글 계정, **When** 구글 로그인을 마치면, **Then** 계정이 만들어지고 구글 이름이 표시 이름으로, 구글이 보낸 이메일과 이메일 검증 여부가 로그인 이메일 정보로 저장되며 가구 없음 화면이 열린다.
3. **Given** 이미 가입한 사용자의 구글 이메일이나 검증 여부가 이전과 달라졌을 때, **When** 다시 로그인하면, **Then** 저장된 값이 구글이 보낸 최신 값으로 바뀐다.
4. **Given** 로그인 도중 구글 인증이 실패하거나 사용자가 취소했을 때, **When** 서비스로 돌아오면, **Then** 로그인 상태는 만들어지지 않고 실패를 알리는 화면에서 로그인을 다시 시작할 수 있다.
5. **Given** 같은 사용자가 휴대폰과 컴퓨터 두 곳에서 로그인한 상태, **When** 휴대폰에서 로그아웃하면, **Then** 휴대폰의 로그인 상태만 삭제되어 휴대폰의 이전 요청은 401로 거절되고, 컴퓨터는 계속 사용할 수 있다.
6. **Given** 로그인한 지 31일이 지났고 마지막 요청은 어제인 로그인 상태, **When** 요청하면, **Then** 만료되어 401로 거절된다. 로그인한 지 10일이지만 마지막 요청이 8일 전인 로그인 상태도 만료되어 거절된다.
7. **Given** 로그인 전에 열려던 서비스 안 경로가 있을 때, **When** 로그인을 마치면, **Then** 그 경로로 간다. 돌아갈 경로가 `/` 다음에 탭이 오는 값, `/%09/x`, `//x`, `/\x`이면 서비스 밖으로 보내지 않고 `/`로 간다.
8. **Given** 로그인한 사용자, **When** 가구 없음 화면을 열면, **Then** "아직 가구가 없습니다" 안내와 로그아웃, 탈퇴 버튼이 보인다. 가구 만들기 버튼과 초대 링크 안내는 002가 추가한다.

### User Story 2 - 민감한 동작 앞에서 구글 인증을 한 번 더 거친다 (Priority: P2)

탈퇴(이 기능이 가진 유일한 민감 동작)는 마지막 구글 인증(재인증 포함)이 5분 안일 때만 처리됩니다. 5분이 지났으면 구글 계정 선택 화면을 한 번 더 거쳐 같은 계정을 고른 뒤 돌아와 같은 버튼을 다시 누릅니다. 마지막 구글 인증은 서비스가 로그인이나 재인증을 마친 시각입니다. 가구 삭제, 구성원 제거, 초대 발급도 같은 민감 동작이며, 그 동작은 002가 같은 방식에 연결합니다.

**Why this priority**: 로그인 상태를 탈취한 사람이 계정 삭제 같은 되돌릴 수 없는 동작을 하는 것을 막는 마지막 방어선입니다.

**Independent Test**: 마지막 인증 시각을 5분 전후로 조정한 로그인 상태로 탈퇴를 요청해 5분 안이면 처리되고 5분 밖이면 401 REAUTH_REQUIRED가 나오는지, 다른 구글 계정으로 재인증하면 실패하고 로그인 상태가 삭제되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 마지막 구글 인증이 5분 안인 로그인 상태, **When** 탈퇴를 요청하면, **Then** 재인증 없이 처리된다.
2. **Given** 마지막 구글 인증이 5분보다 오래되었거나 기록이 없거나 현재 시각보다 60초 넘게 미래인 로그인 상태, **When** 탈퇴를 요청하면, **Then** 401과 코드 REAUTH_REQUIRED로 응답하고 동작은 처리되지 않는다. 화면은 구글 재인증을 안내한다.
3. **Given** 재인증을 마치고 돌아왔을 때, **When** 화면이 열리면, **Then** 이전에 누른 동작은 자동으로 다시 보내지지 않고, 사용자가 같은 버튼을 다시 눌러야 처리된다. 그 동작과 입력값은 브라우저 저장소, 화면 주소, 돌아갈 경로 어디에도 남지 않는다.
4. **Given** 현재 로그인한 구글 계정과 다른 구글 계정으로 재인증했을 때, **When** 서비스로 돌아오면, **Then** 재인증은 실패하고 현재 로그인 상태도 삭제되어 로그인 화면으로 간다.
5. **Given** 재인증에 성공했을 때, **When** 서비스로 돌아오면, **Then** 새 로그인 상태가 발급되고 이전 로그인 상태는 삭제되며 로그인한 지 30일을 다시 센다.
6. **Given** 만료되었거나 삭제된 로그인 상태, **When** 탈퇴를 요청하면, **Then** 마지막 인증이 오래되었더라도 REAUTH_REQUIRED가 아니라 일반 401로 응답한다(로그인 상태 확인이 재인증 확인보다 먼저다).

### User Story 3 - 탈퇴한다 (Priority: P2)

로그인한 사용자가 가구 없음 화면에서 탈퇴(자기 계정 삭제)를 누르면 삭제되는 것을 알리는 확인 화면을 거치고, 마지막 구글 인증이 5분 안이어야 처리됩니다. 처리되면 계정과 모든 기기의 로그인 상태가 삭제됩니다.

**Why this priority**: 서비스를 그만두는 길이 없으면 개인정보를 사용자가 거둘 수 없습니다. 재인증 메커니즘이 처음 쓰이는 동작이기도 합니다.

**Independent Test**: 가짜 구글 계정으로 로그인해 탈퇴하면 계정과 모든 로그인 상태가 삭제되는지, 두 기기에서 로그인한 상태에서 한 기기에서 탈퇴하면 다른 기기의 요청도 거절되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 가구 없음 화면의 사용자, **When** 탈퇴를 누르면, **Then** 삭제되는 것(계정, 로그인 이메일, 표시 이름, 모든 기기의 로그인 상태)과 되돌릴 수 없다는 안내가 있는 확인 화면이 먼저 보이고, 확인해야 탈퇴가 진행된다. 마지막 인증이 5분보다 오래되었으면 재인증을 거친 뒤 같은 버튼을 다시 누른다.
2. **Given** 확인 화면에서 취소했을 때, **When** 가구 없음 화면으로 돌아오면, **Then** 계정과 로그인 상태는 바뀌지 않는다.
3. **Given** 확인을 마친 탈퇴, **When** 처리되면, **Then** 사용자 정보와 그 사람의 모든 기기의 로그인 상태가 실제로 삭제되고 로그인 화면으로 간다. 이전 로그인 상태로 요청하면 401로 거절된다.
4. **Given** 같은 사용자가 두 기기에서 로그인한 상태, **When** 한 기기에서 탈퇴하면, **Then** 다른 기기의 다음 요청도 401로 거절된다.
5. **Given** 탈퇴한 구글 계정, **When** 다시 로그인하면, **Then** 처음 로그인하는 계정으로 취급된다.

### User Story 4 - 내 정보를 조회하고 표시 이름을 수정한다 (Priority: P3)

로그인한 사용자가 자기 표시 이름과 로그인 이메일, 이메일 검증 여부를 조회하고, 표시 이름을 수정할 수 있습니다. 구글이 이름을 보내지 않아 비어 있으면 직접 입력합니다. 이 기능에는 입력 화면이 없고 요청(API)으로만 제공하며, 화면은 002가 가족 초대 화면에 둡니다.

**Why this priority**: 구글 계정 이름이 가족끼리 부르는 이름과 다를 수 있어 서로 알아볼 수 있게 하려는 보조 기능이고, 이름이 쓰이는 목록 화면은 002에 있습니다.

**Independent Test**: 내 정보를 조회해 표시 이름과 로그인 이메일과 검증 여부가 보이는지, 이름을 수정하면 조회에 새 이름이 나오는지, 빈 이름이 거절되는지 확인합니다.

**Acceptance Scenarios**:

1. **Given** 로그인한 사용자, **When** 내 정보를 조회하면, **Then** 자기 표시 이름, 로그인 이메일, 이메일 검증 여부가 응답에 담긴다. 로그인하지 않은 요청은 401이다.
2. **Given** 구글 계정 이름이 표시 이름으로 저장된 사용자, **When** 새 이름을 저장하면, **Then** 이후 조회에 새 이름이 나온다.
3. **Given** 구글이 이름을 보내지 않은 사용자, **When** 처음 로그인하면, **Then** 표시 이름이 비어 있고, 직접 입력해 저장할 수 있다.
4. **Given** 로그인한 사용자, **When** 빈 이름이나 한도를 넘는 긴 이름을 저장하려 하면, **Then** 저장되지 않고 이유를 응답한다(길이 한도는 plan이 정한다).

### Edge Cases

- 구글 로그인을 시작한 뒤 10분 안에 마치지 못하면 로그인을 처음부터 다시 시작해야 합니다.
- 구글이 이메일을 검증하지 않았다고 보낸 사용자도 로그인할 수 있고, 검증 여부는 내 정보에 그대로 담깁니다.
- 한 번 재인증하면 5분 안에는 탈퇴를 다시 시도해도 재인증을 요구하지 않습니다.
- 같은 사용자가 여러 기기에서 각각 로그인한 상태에서 한 기기가 로그아웃해도 다른 기기는 계속 사용할 수 있습니다. 모든 기기의 로그인 상태가 사라지는 것은 탈퇴뿐입니다.
- 초대 링크로 들어온 사람이 로그인하는 흐름은 002가 만듭니다. 이 기능은 로그인 뒤 돌아갈 경로를 서비스 안 경로로만 허용하는 규칙(US1 7번)까지만 책임집니다.
- 로그인 토큰 원문과 로그인 이메일 원문은 서비스 로그와 오류 메시지에 평문으로 남지 않습니다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 구글 계정으로만 로그인할 수 있게 해야 한다. 이메일과 비밀번호, 메일 링크, 카카오 로그인은 제공하지 않는다.
- **FR-002**: 시스템은 로그인하지 않은 사람에게 로그인 화면 외의 화면과 자료를 보여 주지 않아야 한다. 어느 화면 주소를 열어도 로그인 화면을 보여 주고, 자료 요청(API)에는 401로 응답한다. 화면을 그리는 파일(HTML, 스크립트)에는 개인 자료가 없다. 로그인 상태 없이 받는 요청은 이 화면 파일과 로그인 시작, 구글에서 돌아오는 콜백뿐이다.
- **FR-003**: 시스템은 처음 로그인한 구글 계정으로 사용자를 만들고, 표시 이름(구글이 보낸 이름, 없으면 빈 값), 로그인 이메일, 이메일 검증 여부를 저장해야 한다. 같은 구글 계정은 하나의 사용자로 식별한다.
- **FR-004**: 시스템은 다시 로그인할 때 구글이 보낸 이메일과 검증 여부가 저장된 값과 다르면 최신 값으로 바꿔야 한다.
- **FR-005**: 시스템은 로그인에 성공하면 가구 없음 화면을 보여 주어야 한다. 로그인 전에 열려던 서비스 안 경로가 있으면 그 경로로 보낸다.
- **FR-006**: 시스템은 로그인 뒤 돌아갈 경로가 서비스 안 경로(`/`로 시작하고, `//`나 `/\`로 시작하지 않으며, 제어 문자와 역슬래시를 포함하지 않음)일 때만 그 경로로 보내고, 그 밖의 값(퍼센트 인코딩을 푼 값 포함)이면 `/`로 보내야 한다.
- **FR-007**: 시스템은 로그인에 실패하거나 취소되면 로그인 상태를 만들지 않고 실패를 알리는 화면에서 로그인을 다시 시작할 수 있게 해야 한다.
- **FR-008**: 시스템은 로그인 상태를 7일 동안 요청이 없으면 만료시키고, 계속 사용해도 로그인한 지 30일이 지나면 만료시켜야 한다. 만료된 로그인 상태의 요청은 401로 거절한다. 로그인할 때마다 새 로그인 상태를 만들며, 같은 사용자가 여러 기기에서 각각 로그인할 수 있다.
- **FR-009**: 시스템은 로그아웃하면 그 기기의 로그인 상태만 삭제하고 로그인 화면으로 보내야 한다. 삭제된 로그인 상태로 한 요청은 401로 거절한다.
- **FR-010**: 시스템은 가구 없음 화면에 "아직 가구가 없습니다" 안내와 로그아웃, 탈퇴 버튼을 보여 주어야 한다. 이 기능에는 가구가 없으므로 모든 로그인한 사용자가 이 화면을 본다.
- **FR-011**: 시스템은 민감 동작(이 기능에서는 탈퇴)을 마지막 구글 인증이 5분 안일 때만 처리해야 한다. 마지막 인증 기록이 없거나, 5분보다 오래되었거나, 현재 시각보다 60초 넘게 미래이면 401과 코드 REAUTH_REQUIRED로 응답한다.
- **FR-012**: 시스템은 로그인과 재인증 모두 사용자가 구글 계정 선택 화면에서 계정을 직접 고르게 하고, 재인증은 고른 계정이 현재 사용자와 같을 때만 성공시키며, 재인증을 마치고 돌아왔을 때 이전 민감 동작을 자동으로 다시 보내지 않아야 한다. 민감 동작과 입력값을 브라우저 저장소, 화면 주소, 돌아갈 경로에 담지 않는다.
- **FR-013**: 시스템은 현재 로그인한 구글 계정과 다른 계정으로 재인증하면 재인증을 실패시키고 현재 로그인 상태도 삭제해야 한다.
- **FR-014**: 시스템은 재인증에 성공하면 새 로그인 상태를 발급하고 이전 로그인 상태를 삭제하며, 로그인한 지 30일을 재인증 시각부터 다시 세야 한다.
- **FR-015**: 시스템은 요청을 로그인 상태(401), 민감 동작의 재인증(401 REAUTH_REQUIRED) 순서로 확인하고 처음 걸린 단계의 상태 코드로 응답해야 한다. 만료되었거나 삭제된 로그인 상태는 마지막 인증 시각과 관계없이 REAUTH_REQUIRED가 아니라 일반 401이다. 멤버십과 역할과 가구 자원에 관한 확인 단계는 002가 이 순서에 더한다.
- **FR-016**: 시스템은 사용자가 탈퇴하면 삭제되는 것을 알리는 확인 화면을 거친 뒤 사용자 정보와 그 사람의 모든 기기의 로그인 상태를 삭제해야 한다. 가구가 있는 사용자의 탈퇴 거절(409)은 002가 더한다.
- **FR-017**: 시스템은 로그인한 사용자가 자기 표시 이름, 로그인 이메일, 이메일 검증 여부를 조회하게 해야 한다. 다른 사용자의 정보는 이 요청으로 조회할 수 없다. 로그인 이메일은 사용자가 서비스 안에서 수정할 수 없다.
- **FR-018**: 시스템은 사용자가 자기 표시 이름만 수정하게 해야 한다. 빈 이름과 한도를 넘는 이름은 저장하지 않는다. 표시 이름 길이의 한도와 허용 문자는 plan이 정한다.
- **FR-019**: 시스템은 로그아웃, 탈퇴, 다른 구글 계정으로 한 재인증 뒤에 해당 로그인 상태가 실제로 삭제되어 같은 로그인 상태로 한 요청이 401로 거절되게 해야 한다.
- **FR-020**: 시스템은 로그인 토큰 원문과 로그인 이메일 원문을 서비스 로그와 오류 메시지에 평문으로 남기지 않아야 한다.
- **FR-021**: 시스템은 모든 화면을 휴대폰 화면 폭에서 가로 스크롤 없이 사용할 수 있게 해야 한다.

### Key Entities *(include if feature involves data)*

- **사용자**: 구글 계정 하나에 대응하는 로그인한 사람. 구글 계정 식별값, 로그인 이메일, 이메일 검증 여부, 표시 이름을 가진다. 같은 구글 계정은 하나의 사용자로 식별한다.
- **로그인 상태**: 사용자가 기기 하나에서 로그인한 기간. 마지막 요청 시각, 로그인한 시각, 마지막 구글 인증 시각을 가진다. 역할은 담지 않는다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 로그인하지 않은 사람이 구글 로그인을 마치면 추가 입력 없이 가구 없음 화면에 도착한다. 로그인 화면에서 가구 없음 화면까지 서비스 쪽 화면 이동은 한 번이다.
- **SC-002**: 탈퇴는 마지막 구글 인증이 5분 안일 때 100% 처리되고, 5분을 넘기면 100% 401 REAUTH_REQUIRED로 거절된다.
- **SC-003**: 다른 구글 계정으로 한 재인증은 100% 실패하고 현재 로그인 상태가 삭제된다.
- **SC-004**: 로그아웃, 탈퇴, 다른 계정 재인증 뒤 해당 로그인 상태로 한 요청은 100% 401로 거절된다. 로그인한 지 30일이 지난 로그인 상태와 7일 동안 요청이 없던 로그인 상태는 100% 거절된다.
- **SC-005**: 돌아갈 경로로 서비스 밖 주소가 될 수 있는 값을 넣은 네 가지 입력은 모두 `/`로 이동한다.
- **SC-006**: 서비스 로그와 오류 메시지에서 로그인 토큰 원문과 로그인 이메일 원문이 평문으로 발견되는 경우가 0건이다.
- **SC-007**: 모든 화면이 휴대폰 화면 폭에서 가로 스크롤 없이 모든 버튼을 누를 수 있다.

## Assumptions

- 사용자는 본인과 가족 구성원 두 명이고, 모두 휴대폰 웹 브라우저로 사용합니다.
- 로그인 화면의 서비스 이름은 임시 이름 "서초댁 임장 기록"입니다. 최종 이름이 정해지면 [용어 표](../../docs/README.md#용어)와 화면 문구를 함께 수정합니다.
- 구글 OAuth 클라이언트 등록은 구현 전에 저장소 소유자가 합니다. 계획과 작업 분해는 등록 전에 진행할 수 있습니다.
- 구글은 재인증 요청을 지원하지 않고 마지막 인증 시각(`auth_time`)도 주지 않으므로, 재인증은 구글 계정 다시 고르기와 같은 계정인지 확인으로 하고 마지막 구글 인증 시각은 서비스가 로그인이나 재인증을 마친 시각으로 둡니다([결정 기록 0013](../../docs/adr/0013-session.md)). 구글에 로그인된 같은 브라우저에서는 비밀번호를 다시 묻지 않을 수 있습니다. 계정 선택 화면이 실제로 뜨는지는 구현 때 실제 구글 계정으로 확인합니다.
- 이 기능에는 가구라는 개념이 없습니다. 가구 만들기, 구성원, 초대, 가구 삭제, 탈퇴 거절(가구가 있는 사람), 표시 이름 수정 화면, 임시 첫 화면은 002(가구와 가족 공유)가 이 기능 위에 더합니다([백로그의 경계 규칙](../../docs/backlog.md)).
- 첫 로그인 때의 알림 설정은 알림 설정을 처음 만드는 뒤 기능(009)이 맡고, 이미 있는 사용자의 자료도 채웁니다.
- 탈퇴의 확인 방식은 설계 문서가 기능 명세에 넘긴 항목입니다. 삭제되는 것을 알리는 확인 화면과 재인증을 거칩니다.
- 표시 이름을 비워서 저장하는 것은 허용하지 않습니다. 첫 로그인에서 구글이 보낸 이름을 다듬은 뒤 쓸 수 있는 이름이 없는 경우(이름을 보내지 않았거나 쓸 수 없는 문자뿐)의 빈 값만 예외입니다.
- 초대 링크 수락과 그 로그인 흐름, 요청이 막히는 순서의 404와 403 단계, 다른 가구 자원 404 테스트는 002가 맡습니다([API 공통 규칙](../../docs/architecture/api-conventions.md#인증과-권한-확인)).
- 구글 로그인 화면, 동의 화면, 계정 선택 화면의 문구와 생김새는 구글이 정하고 이 서비스의 범위 밖입니다. 이 서비스는 계정 선택 화면을 띄우라고 요청합니다(FR-012).
- 범위 밖: 가구, 구성원, 초대, 매물, 호가, 임장 기록, 관심 단지, 알림, 읽기 전용 역할, 카카오 로그인, 로그인 허용 목록, 알림 메일 주소 변경, 로그인한 기기 목록과 기기별 로그아웃(2단계 후보).
